# Spec: parity residual map — measured true byte-parity state

## Measured state (dual-fresh oracle methodology)

The `/tmp/ares-parity-fresh/` sweep corpus is stale on BOTH sides (stored
`orca.gcode` is one non-deterministic snapshot; stored `ares.gcode` predates
the current binary). The only valid verdict regenerates BOTH: pass iff
`diff(ares, oracle_run) ≤ max(2, oracle_self_diff)` across ≥2 oracle runs.

On a 20-case random dual-fresh sample + targeted re-verification:

- **~80–95% of sampled cases are byte-identical to at least one genuine
  oracle run** (`aresB == 0` or `aresA == 0`), including previously-flagged
  "failures" (`case-090y6B`, `case-03RaeG` cooling-F) that resolve to oracle
  run-to-run ordering variance (M73 placement, `connectJunctions` quad order,
  concentric survivors, cooling-line TBB race).
- The parity harness (`orca_parity.rs::compare_exported_for`) already encodes
  this correctly: on DIVERGENT it re-slices the oracle up to `ARES_ORCA_RUNS`
  (default 3) and passes if ares matches ANY genuine oracle output. The
  `generated by` timestamp is the only normalized line.

## Confirmed oracle non-determinism (do NOT chase)

- M73 `P`/`R` ordering position (TBB emit race).
- `connectJunctions` quad order (`ankerl::unordered_dense::set` pointer-hash
  iteration order).
- Cooling-line `sort_lines_by_decreasing_feedrate` order on equal feedrates.
- Tiny concentric loop survivors.

## Deterministic residuals (real, localized)

1. **wipe-E per-segment split** (`case-59tGO2` family, ~3600 lines).
   `motion/travel.rs:230` `during·(segment_length/distribution_distance)`.
   Emitted wipe `F` matches oracle byte-exact → `wipe_speed` is correct; the
   residual is `retraction_distance`/`distribution_distance`/per-segment
   `segment_length` drifting ~1e-5. Candidate: `wipe_path.rs:40` re-rounds
   `wipe_path[1:]` through `/scale.round()` while oracle `Wipe::wipe`
   (`GCode.cpp:344-360`) uses `path.points` `coord_t` ints raw for
   `wipe_path.length()`. Needs `ORCA_WIPEDUMP` per-segment `slen`/`dE` compare.

2. **cooling-feedrate Newton output** (`F3381`/`F2963` class).
   `slowdown.rs` port is verified input-identical to `CoolingBuffer.cpp`;
   residual is upstream narrow-region `split_lines` producing one extra
   micro-fragment → `nadj`/`total` shift → Newton landing point differs.
   Root is path-grouping parity in `group_fills/narrow/split.rs` vs
   `FillRectilinear.cpp`, not the Newton itself.

3. **M73 time-accumulator ordering** (`case-aBhv1I` — pure ordering, zero
   value diffs). `processor/estimate.rs` `elapsed_at(index+1)` sums
   `block.time` vs oracle `GCodeProcessor` trapezoid model; a small
   systematic accumulator drift fires `M73 P` a few extrusions late.

4. **raft structural** (`case-n4acJn` self=0 ares=3182, `case-59tGO2`).
   Residual in raft sheath/connect geometry after the flange fix; needs
   raft polygon probe (existing `ARES_INNER_CONTOUR`/`PLANPOLY`/`OUTPOLY`
   dumps) to localize which intermediate polygon diverges.
