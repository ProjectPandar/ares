# Spec: parity residual map — measured true byte-parity state

## Measured state (dual-fresh oracle methodology)

The `/tmp/ares-parity-fresh/` sweep corpus is stale on BOTH sides (stored
`orca.gcode` is one non-deterministic snapshot; stored `ares.gcode` predates
the current binary). The only valid verdict regenerates BOTH: pass iff
`diff(ares, oracle_run) ≤ max(2, oracle_self_diff)` across ≥2 oracle runs.

On a 20-case random dual-fresh sample + targeted re-verification:

- **~80–95% of sampled cases are byte-identical to at least one genuine
  oracle run** (`aresB == 0` or `aresA == 0`), including previously-flagged
  "failures" (`case-090y6B`, `case-03RaeG` cooling-F) that resolve to oracle
  run-to-run ordering variance (M73 placement, `connectJunctions` quad order,
  concentric survivors, cooling-line TBB race).
- The parity harness (`orca_parity.rs::compare_exported_for`) already encodes
  this correctly: on DIVERGENT it re-slices the oracle up to `ARES_ORCA_RUNS`
  (default 3) and passes if ares matches ANY genuine oracle output. The
  `generated by` timestamp is the only normalized line.

## Confirmed oracle non-determinism (do NOT chase)

- M73 `P`/`R` ordering position (TBB emit race).
- `connectJunctions` quad order (`ankerl::unordered_dense::set` pointer-hash
  iteration order).
- Cooling-line `sort_lines_by_decreasing_feedrate` order on equal feedrates.
- Tiny concentric loop survivors.

## Plan

- Continue source-cited port slices per the milestone chain; each residual
  above is probe-bound (oracle `Wipe::wipe`/`FillRectilinear`/
  `GCodeProcessor` instrumentation) and converges one family per cycle.
- Keep the dual-fresh verdict as the parity metric; do not weaken the
  strict byte comparator or add tolerances.
- Option-coverage sweep (Boolean/Enum every value, Range min/max/interior)
  runs through `option_coverage/` against the live oracle.

5. **lightning propagated-tree branch retention** (`case-IdM3Br`, layers 6-19).
   After round-4 (`stable_sort_by` + `coord_t` width cast + `EPSILON` 1e-4),
   propagated trees now retain children during `propagateToNextLayer`
   (PROPAGATE debug: `children=1` most layers) and the tree roots propagate
   continuously 42→6 (cur_roots=4). The residual: layers 6-19 emit **0**
   sparse infill lines while oracle emits a steady 5-6/layer. Diagnosis: the
   model shrinks going UP, so `overhang_per_layer` (shrunk infill minus the
   *wider* layer above) is empty on those layers → `generateNewTrees` seeds
   nothing; oracle's 5/layer therefore comes entirely from propagated-tree
   branches retained by `realign`. Ares's `realign` lifts every child that
   exits the shrunk outline into `rerooted_parts` and clears the parent's
   `children`, and on a monotonically-shrinking outline *all* children exit →
   the lifted roots arrive leaf-less (`C2LT children=[]`) → `convert_to_polylines`
   emits 0. The divergence is inside `prune`/`straighten`/`realign` numerics —
   upstream retains enough branch to emit ~5/layer. `prune` endpoint + `straighten`
   single-child move + colinear-removal were verified faithful to
   `TreeNode.cpp:313,235`; the remaining suspect is `realign`'s
   `line_segment_polygons_intersection` threshold (`outline_locator.resolution()*2`)
   vs upstream `TreeNode.cpp:196-228`, or `reconnectRoots` failing to re-ground
   lifted parts back into the boundary where upstream keeps them attached.
