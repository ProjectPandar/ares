# Consume BTT Thumbnail Header Skip Design

## Source Boundary

This slice ports the Orca G-code export branch in `OrcaSlicer/src/libslic3r/GCode.cpp` where `_do_export` checks `print.config().option<ConfigOptionString>("thumbnails")->value`, searches for the `BTT_TFT` label, and skips the header block when that label is present. The related thumbnail vocabulary is the `GCodeThumbnailsFormat` enum in `OrcaSlicer/src/libslic3r/PrintConfig.hpp` and the BTT thumbnail export path in `OrcaSlicer/src/libslic3r/GCode/Thumbnails.hpp`.

## Ares Boundary

Ares already parses and normalizes `thumbnails` / `thumbnails_format` into canonical strings such as `7x8/BTT_TFT` in `crates/ares-core/src/gcode_thumbnails.rs` and `crates/ares-core/src/options/legacy/thumbnails.rs`. This slice consumes that existing option value at the G-code export boundary:

- `crates/ares-core/src/gcode.rs` decides whether to emit the Ares header before the preamble.
- `crates/ares-core/src/gcode_header.rs` may expose a small helper for detecting a BTT thumbnail from normalized options.
- `crates/ares-core/src/tests` gets a regression test proving a BTT thumbnail option suppresses the header while keeping layer G-code output.

## Behavior

When the normalized `thumbnails` option contains a parsed `BTT_TFT` thumbnail entry, Ares must skip `gcode_header::format_header(...)`. This removes the generated Ares header comment lines such as `; generated by Ares`, `; input_format = ...`, and the aggregate pipeline counts from the output. The rest of the G-code export remains unchanged: file-start custom G-code stays at the top, the writer preamble still follows, startup temperature/custom G-code still emits, and layer/toolpath G-code still emits.

When `thumbnails` is absent, empty, a non-string value, or contains only non-BTT formats such as `PNG`, `JPG`, `QOI`, or `COLPIC`, Ares must keep emitting the header exactly as before.

Invalid thumbnail values are already handled by existing option normalization and parsing behavior. This slice must not add new option metadata, new dependencies, image generation, base64 thumbnail output, or a thumbnail callback API.

## Acceptance Criteria

- A JSON option set with `"thumbnails": "7x8/btt_tft"` suppresses `; generated by Ares` and other header-only comments in the final G-code.
- The same BTT case still contains normal layer output such as `;LAYER_CHANGE` and movement commands.
- A JSON option set with `"thumbnails": "7x8/png"` preserves the existing header.
- Existing legacy thumbnail normalization remains intact and still canonicalizes BTT entries to `BTT_TFT`.
- `cargo test -p ares-core --lib` passes.
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `git diff --check`, and the Rust file LOC gate pass.

## Deferred Behavior

This slice does not implement thumbnail image rendering, BTT binary payload output, `THUMBNAIL_BLOCK_START` output for non-BTT thumbnails, CONFIG_BLOCK output, Bambu printer-specific header fields, or full Orca `GCodeThumbnails::export_thumbnails_to_file` parity. It only ports the existing Orca header-suppression branch that is directly reachable from the already-normalized `thumbnails` option.
