# Consume Seam Position Back Design

## Goal

Consume OrcaSlicer's existing `seam_position = "back"` option into concrete Ares perimeter start-point behavior so configured rectangular perimeters and their downstream print paths/G-code start at the rear-most available loop vertex instead of only carrying option metadata.

## Upstream Rewrite Boundary

- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:211-213` defines `enum SeamPosition { spNearest, spAligned, spAlignedBack, spRear, spRandom }`.
- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:944` includes `((ConfigOptionEnum<SeamPosition>,  seam_position))` in `PrintObjectConfig`.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:350-357` maps the serialized keys `nearest`, `aligned`, `aligned_back`, `back`, and `random`.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:5357-5373` registers `seam_position`, describes it as the start position for each outer wall part, and defaults to `spAligned`.
- `OrcaSlicer/src/libslic3r/GCode/SeamPlacer.cpp:742-797` defines `SeamComparator`; for `spRear`, lines `777-779` prefer the candidate with greater Y.
- `OrcaSlicer/src/libslic3r/GCode/SeamPlacer.cpp:1433-1492` reads `po->config().seam_position.value`, chooses seam points for non-`spNearest`, and aligns `spAligned`, `spRear`, and `spAlignedBack`.

## Ares Destination Boundary

- `crates/ares-core/src/perimeters/options.rs` owns the Rust `SeamPosition` enum and `PerimeterOptions` field/accessors.
- `crates/ares-core/src/options/overhang_reverse.rs` owns parsing from `SliceOptions` into `PerimeterOptions`.
- `crates/ares-core/src/perimeters.rs` owns the current perimeter loop point order and will rotate loop vertices before `PerimeterPath::new`.
- `crates/ares-core/src/perimeters/tests.rs` and `crates/ares-core/src/pipeline/tests/wall_direction.rs` provide focused perimeter and G-code regression coverage.

## Included Behavior

- Parse `seam_position` string values `nearest`, `aligned`, `aligned_back`, `back`, and `random` into a Rust enum.
- Default omitted `seam_position` to `aligned`, matching Orca's `spAligned` default.
- Reject malformed `seam_position` values at the `SliceOptions::perimeter_options()` boundary with `SliceError::InvalidInput` naming `seam_position`.
- Implement concrete runtime behavior for `back`: rotate every generated perimeter loop so the first point is the first existing vertex with the largest Y coordinate after wall-direction, overhang-reverse, fuzzy-skin, and internal-loop generation have produced final loop point order.
- Preserve loop orientation; only rotate the point vector.
- Apply the same rotation to external, internal, and extra overhang perimeter loops generated by Ares so downstream print paths and G-code comments consume the configured start point.
- Preserve the current default `aligned` output for existing tests and callers.

## Deferred Behavior

- Full Orca `SeamPlacer` candidate generation, seam blockers/enforcers, visibility/occlusion, overhang penalties, embedded-distance penalties, angle penalties, and B-spline seam alignment.
- Runtime behavior differences for `nearest`, `aligned`, `aligned_back`, and `random`; they parse now but retain the existing deterministic Ares start order until their source-cited slices are implemented.
- Nozzle-position-dependent nearest seam selection, stochastic random seam selection, seam projection into extrusion loops, scarf seam behavior, staggered inner seams, seam gap geometry, multi-object coordination, and UI/runtime preset behavior.

## Acceptance Criteria

- `cargo nextest run -p ares-core seam_position` has a RED failure after tests are added and before production code changes.
- The GREEN implementation makes `seam_position = "back"` produce perimeter and print-path G-code markers beginning at the rear-most vertex on the rectangular test pipeline.
- A direct perimeter unit test proves `SeamPosition::Back` rotates a square external loop from the default lower-front start to the first max-Y vertex while preserving order.
- A parsing test proves omitted `seam_position` defaults to `SeamPosition::Aligned`.
- A parsing test proves invalid `seam_position` returns `SliceError::InvalidInput` and mentions `seam_position`.
- Existing `wall_direction`, `wall_sequence`, `overhang_reverse`, and fuzzy-skin behavior remains compatible because seam rotation happens after those transforms.
- Full verification before commit uses `cargo fmt --check`, focused `cargo nextest run -p ares-core seam_position`, `cargo nextest run --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo check -p ares-core --target wasm32-unknown-unknown`, `git diff --check`, `git diff --cached --check`, and touched Rust LOC checks.

## Safety And Rollback

The change is limited to `ares-core` option parsing and in-memory perimeter point order. It adds no dependencies, file I/O, terminal behavior, UI behavior, OpenGL, or platform-specific code. Rollback is a single revert of the slice commit, restoring the current canonical contour start order.

## Documentation Impact

Update `docs/roadmap.md` after implementation review to record that `seam_position = "back"` is now consumed as a concrete perimeter/print-path/G-code start-point behavior while the rest of Orca `SeamPlacer` remains deferred.
