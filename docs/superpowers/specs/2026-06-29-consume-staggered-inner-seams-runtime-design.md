# Consume `staggered_inner_seams` Runtime Design

## Goal

Consume OrcaSlicer's `staggered_inner_seams` option in Ares' existing perimeter runtime so rectangular internal perimeter loops can shift their seam starts when the option is enabled.

This slice is intentionally bounded to the perimeter behavior Ares already owns today: rectangular perimeter loops, existing `seam_position` parsing, existing G-code path emission, and no new seam-candidate, scarf, Arachne, or support-generation machinery.

## Upstream Source Boundary

- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:944-945` declares `seam_position` followed by `staggered_inner_seams` in `PrintObjectConfig`.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:5375-5380` registers `staggered_inner_seams` as a boolean quality option, describes it as shifting inner seams backwards based on depth to form a zigzag pattern, and defaults it to `false`.
- `OrcaSlicer/src/libslic3r/GCode/SeamPlacer.cpp:1601-1619` applies the runtime behavior only for internal perimeter loops: if `staggered_inner_seams` is enabled and the loop has length, Orca clamps the shift depth to at least the loop path width, walks to the next loop point while depth remains, and uses the resulting point as the seam point.
- `OrcaSlicer/src/libslic3r/GCode/SeamPlacer.cpp:1622-1628` then splits the loop at that seam point, inserting the point when it is not already a loop vertex.

## Ares Destination Boundary

- `crates/ares-core/src/options/overhang_reverse.rs` will parse `staggered_inner_seams` with Orca's default of `false`.
- `crates/ares-core/src/perimeters/options.rs` will store the option in `PerimeterOptions` with a builder and getter.
- `crates/ares-core/src/perimeters.rs` will delegate seam placement to a new focused `crates/ares-core/src/perimeters/seams.rs` module to keep `perimeters.rs` under the 400 LOC project limit. The existing `rotate_for_seam_position` and `first_max_y_index` helpers move into `seams.rs`; `perimeters.rs` should lose more LOC than the new call-site arguments add, and the new module should stay small and single-purpose.
- `crates/ares-core/src/perimeters/tests/staggered_inner_seams.rs` and `crates/ares-core/src/pipeline/tests/staggered_inner_seams.rs` will cover path-level and G-code-visible behavior. The pipeline module gets a dedicated test file for discoverability instead of adding another seam case to `wall_direction.rs`.
- `docs/roadmap.md` will receive a source-cited runtime-slice entry. Historical milestone docs such as `docs/milestones/m106-print-config-restart-speed-seam-registry.md` remain unchanged because their deferral statements describe the state of those historical registry milestones, not the current roadmap state after this slice.

## Runtime Behavior

When `staggered_inner_seams` is `false`, Ares perimeter output must remain unchanged.

When `staggered_inner_seams` is `true`, Ares will apply the option only to closed internal perimeter loops generated by the current rectangular wall-loop code and only after the existing `seam_position` placement has selected a concrete start point. Because Ares currently has concrete seam relocation only for `SeamPosition::Back`, the first runtime slice will make the option observable for `seam_position = "back"` and leave non-Back seam modes unchanged until their upstream-equivalent seam placement exists.

For an internal rectangular loop with `seam_position = "back"`:

1. Rotate to the existing rear seam point, preserving current `Back` behavior.
2. Compute the loop's Ares-known depth from the existing rectangular shrink distance for that wall loop.
3. Clamp the stagger distance to at least `internal_line_width`, matching Orca's `std::max(loop path width, depth)` behavior.
4. Move forward by that stagger distance along the rectangular loop's edges in the same loop direction as Orca's "get next loop point while depth remains" traversal.
5. Interpolate when the stagger distance falls inside a rectangle edge, insert that computed seam point as the first point, and include the previous seam vertex at the end of the point list so the closed loop geometry is preserved before normal seam-gap shortening.

This produces the intended zigzag-visible seam start for inner loops without changing external perimeters, overhang perimeters, skirt/brim paths, infill, support paths, or G-code emission outside the affected internal perimeter coordinates.

For Ares' current concentric rectangular wall loops, the per-loop shrink distance is the perpendicular depth from the outer seam reference to the internal loop. That makes the `depth` to `shrink` mapping a faithful special-case port of Orca's depth-based staggering. The interpolation step is an explicit compatibility-shell adaptation: Orca walks dense extrusion-loop vertices, while Ares' current rectangular loops have only four vertices, so a literal vertex walk would jump to a corner and lose the intended depth-proportional seam shift.

## Deferred Upstream Behavior

- Full Orca `SeamPlacer` candidate selection, nearest/aligned/random semantics, concave-corner projection, scarf seams, Arachne/T-junction loop handling, and object-level seam history remain out of scope.
- Non-rectangular internal perimeter generation remains out of scope because Ares currently keeps only external loops for non-rectangular contours.
- Exact dense-polyline vertex-walk parity remains out of scope for this rectangular compatibility shell; Ares uses edge arc-length interpolation to preserve Orca's depth-proportional seam shift on four-corner loops.
- Support, bridge, wipe tower, or UI behavior is not part of this option slice.
- Full Orca binary E2E seam parity remains deferred. This slice's executable checks use source-cited Orca algorithm provenance plus Ares G-code token assertions for the concrete rectangular compatibility shell, matching the repository's current runtime-slice test pattern.

## Acceptance Criteria

- `SliceOptions::default().perimeter_options()` yields `staggered_inner_seams() == false`.
- JSON `{ "staggered_inner_seams": true }` yields `staggered_inner_seams() == true`.
- JSON non-boolean values for `staggered_inner_seams` are rejected through the existing boundary parser.
- With `staggered_inner_seams = false`, existing seam-position and seam-gap tests still pass without expected-output changes.
- With `staggered_inner_seams = true`, `seam_position = "back"`, and at least two rectangular wall loops, the external perimeter path is unchanged while internal perimeter path start points shift along the loop and may include an inserted split point.
- With `staggered_inner_seams = true` and a non-Back `seam_position`, perimeter output remains unchanged for this slice.
- Formatted G-code shows the affected internal perimeter `;PERIMETER` and `;PRINT_PATH` start at the staggered point, and the corresponding path-start `;MOVE:travel:internal_perimeter:` travels to that point before print moves continue around the loop.
- `docs/roadmap.md` records the completed runtime slice with the same upstream source boundaries and deferred behavior, while historical milestone docs remain unchanged.
- All touched Rust files stay at or below 400 LOC.
- Verification passes with targeted nextest, `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo check -p ares-core --target wasm32-unknown-unknown`, `cargo nextest run --workspace`, `git diff --check`, and `git diff --cached --check` before commit.

## Safety And Rollback

The option defaults to false, so existing callers keep current behavior unless they explicitly opt in. The change is isolated to perimeter option parsing and internal perimeter point ordering; rollback is a small revert of the new seam module, option field, parser hook, tests, and this design/plan documentation.
