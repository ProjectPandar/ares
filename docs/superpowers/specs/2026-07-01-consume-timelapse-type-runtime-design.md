# Consume Timelapse Type Runtime Design

## Goal

Consume the already-registered Orca `timelapse_type` option as typed Ares runtime state before G-code formatting returns output, without adding timelapse capture, warning, prime-tower mutation, or insertion behavior.

## Upstream Boundary

- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:281-284`: `TimelapseType` enum with `tlTraditional = 0` and `tlSmooth`.
- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:1615`: `ConfigOptionEnum<TimelapseType> timelapse_type`.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:431-435`: `TimelapseType` enum string map.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:5728-5743`: `timelapse_type` option definition, enum values `0` and `1`, labels `Traditional` and `Smooth`, default `tlTraditional`.
- `OrcaSlicer/src/libslic3r/GCode.cpp:2129-2140,4514-4540,4982-5478`: downstream warning and timelapse G-code insertion behavior that reads `timelapse_type`.
- `OrcaSlicer/src/libslic3r/GCode/GCodeProcessor.hpp:244-245` and `GCodeProcessor.cpp:6030-6058`: downstream warning result fields and emitted warning messages.

## Current Ares Boundary

- Registry metadata for `timelapse_type` already exists from the M112 registry slice.
- Legacy normalization rewrites direct `timelapse_type = "2"` to `"0"`, while `timelapse_no_toolhead` only renames the key to `timelapse_type` and preserves the value. Existing legacy tests lock that distinction.
- `options/fdm_normalization.rs` has a private string parser for prime-tower normalization, but there is no crate-private typed runtime accessor that can be consumed by G-code formatting. Leave that private parser untouched in this slice; it shares the same current `"0"`/`"1"` contract for the prime-tower branch.
- `time_lapse_gcode` custom G-code is already rendered by Ares independently of `timelapse_type`; this slice must not change that output behavior.

## Design

Add a focused crate-private `options::timelapse_type` module with:

- `pub(crate) TimelapseType` enum, deriving `Clone`, `Copy`, `Debug`, `Eq`, and `PartialEq`:
  - `Traditional`
  - `Smooth`
- `pub(crate) TimelapseTypeOptions` struct wrapping the selected mode, deriving `Clone`, `Copy`, `Debug`, `Eq`, and `PartialEq`.
- `pub(crate) const fn TimelapseTypeOptions::mode(self) -> TimelapseType`.
- `pub(crate) fn TimelapseTypeOptions::consume_runtime(self)` that reads the accessor to satisfy warning-denied builds without adding behavior.
- `pub(crate) fn SliceOptions::timelapse_type_options() -> Result<TimelapseTypeOptions, SliceError>`.
- Invalid values must return `SliceError::InvalidInput`.

Parsing must accept the current Orca serialized enum strings:

- omitted `timelapse_type` defaults to `Traditional`.
- `"0"` parses as `Traditional`.
- `"1"` parses as `Smooth`.
- `"2"` parses as `Traditional` only to preserve current legacy-carried compatibility: direct legacy `timelapse_type = "2"` is already normalized to `"0"` during deserialization, and legacy `timelapse_no_toolhead = "2"` is renamed while preserving `"2"`.
- all other values are invalid, including numeric `0`/`1`/`2`, unsupported strings such as `"3"`, `"traditional"`, and `"smooth"`, booleans, arrays, objects, and null.

Consume this accessor from `gcode::format_gcode()` before generated bytes are returned. Because `crates/ares-core/src/gcode.rs` is already at 400 LOC and rustfmt will not keep two long option-consumption statements on one line, add a small crate-private `gcode_runtime_options` module. It must expose `consume(options: &SliceOptions) -> Result<(), SliceError>`, call both `options.preheat_options()?.consume_runtime()` and `options.timelapse_type_options()?.consume_runtime()`, and return `Ok(())`. Replace the existing preheat-only line in `gcode.rs` with `crate::gcode_runtime_options::consume(options)?;`, which is line-neutral in `gcode.rs`; add `mod gcode_runtime_options;` to `lib.rs`, which is below the 400 LOC threshold.

Module registration must also be line-neutral in saturated files:

- Add `timelapse_type` to the existing `#[rustfmt::skip] option_modules!(..., preheat, temperature_vector, ...)` line in `crates/ares-core/src/options.rs`, not as a standalone `mod` line.
- Add `timelapse_type` to the existing `#[rustfmt::skip] option_test_modules!(..., temperature_vitrification_runtime, preheat)` line in `crates/ares-core/src/options/tests.rs`, not as a standalone `mod` line.

## Behavior Included

- Invalid `timelapse_type` is rejected on the G-code formatting path before output bytes are returned, even when FDM normalization did not inspect prime-tower behavior. This intentionally tightens configs that previously carried invalid `timelapse_type` values through non-prime-tower G-code generation; rollback is the removal of the `gcode_runtime_options::consume(options)?` call.
- Valid omitted, `"0"`, `"1"`, and legacy-carried `"2"` values preserve current generated command output.
- Direct legacy `timelapse_type = "2"` after deserialization parses as `Traditional` through the existing normalization to `"0"`.
- Legacy `timelapse_no_toolhead = "2"` after deserialization parses as `Traditional` without changing the existing key-alias normalization behavior.
- The parser and tests document Orca defaults and supported enum values.

## Behavior Deferred

- Timelapse capture and video behavior.
- `timelapse_warning_code` computation and warning emission.
- Smooth-timelapse prime-tower enforcement beyond existing normalization behavior.
- Traditional timelapse support flags.
- Wipe-tower timelapse behavior.
- `time_lapse_gcode` insertion changes.
- UI, CLI, WASM binding changes.
- Orca binary E2E timelapse parity.

## Acceptance Criteria

- New option tests prove default, accepted values, rejected values, and `consume_runtime()`.
- New option tests prove direct legacy `timelapse_type = "2"` after deserialization and legacy `timelapse_no_toolhead = "2"` both resolve to `Traditional`.
- New G-code tests prove invalid values reject before output and valid values preserve command output.
- `crates/ares-core/src/options.rs`, `crates/ares-core/src/options/tests.rs`, and `crates/ares-core/src/gcode.rs` remain at or below 400 LOC after `cargo fmt`.
- Verification passes with:
  - `cargo fmt --check`
  - `git diff --check`
  - `cargo check -p ares-core --target wasm32-unknown-unknown`
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo nextest run -p ares-core timelapse_type`
  - `cargo nextest run --workspace`
