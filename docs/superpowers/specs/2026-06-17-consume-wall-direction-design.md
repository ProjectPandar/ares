# Consume Wall Direction Design

## Goal

Consume Orca `wall_direction` as concrete perimeter path behavior in Ares instead of leaving it as registry/metadata-only option coverage.

## Upstream Boundary

- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:139-145` defines `enum class WallDirection` with `CounterClockwise`, `Clockwise`, and `Count`.
- `OrcaSlicer/src/libslic3r/PrintConfig.hpp:1212` declares the `PrintRegionConfig` `wall_direction` option tuple.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:288-292` maps enum keys `"ccw"` and `"cw"` to `WallDirection`.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:2100-2110` defines `wall_direction` as `coEnum`, exposes values `"ccw"` and `"cw"`, and defaults to `CounterClockwise`.
- `OrcaSlicer/src/libslic3r/PrintConfig.cpp:8065-8067` migrates legacy `wall_direction = "auto"` to `"ccw"`; Ares already ports this ingestion behavior.
- `OrcaSlicer/src/libslic3r/PerimeterGenerator.cpp:260-263` and `:529-533` orient contour loops according to `wall_direction`, while holes are oriented opposite to contours.

## Current Ares State

- `crates/ares-core/src/options/registry/definitions/table/tail_terminal_suffix.rs` registers `wall_direction` metadata with default `"ccw"`.
- `crates/ares-core/src/options/legacy.rs` normalizes legacy `"auto"` to `"ccw"`.
- `SliceOptions::perimeter_options()` does not parse `wall_direction`.
- `PerimeterOptions` only carries wall-loop count and perimeter line widths.
- `generate_perimeters()` currently preserves normalized contour point order for external loops and creates rectangular internal loops in the same counter-clockwise point order.

## Design

Add a runtime `WallDirection` enum in the perimeter domain with `CounterClockwise` and `Clockwise` variants. Parse Orca option values `"ccw"` and `"cw"` from `SliceOptions::perimeter_options()`, defaulting to `CounterClockwise`.

`PerimeterOptions` will carry the parsed wall direction. `generate_perimeters()` will orient every contour perimeter path generated by the current Ares perimeter model:

- `CounterClockwise`: keep existing point order.
- `Clockwise`: reverse the external contour path and each generated rectangular internal wall path.

This ports the contour-loop part of Orca's runtime behavior that Ares can represent today. It intentionally does not invent Ares-only behavior for missing upstream concepts.

## Deferred Upstream Behavior

- Hole orientation remains deferred because current Ares `LayerContours` does not distinguish contour loops from hole loops.
- Arachne extrusion-line orientation remains deferred because Ares does not yet model Orca Arachne perimeter generation.
- `overhang_reverse`, `overhang_reverse_internal_only`, fuzzy-skin reversal, thin-wall-hole ordering, and wall-sequence reordering remain deferred; they are adjacent Orca `PerimeterGenerator.cpp` behavior outside this slice.
- Spiral vase disabling/UI behavior remains deferred because Ares core has no UI control state and this slice does not port vase-mode perimeter generation.

## Acceptance Criteria

- `SliceOptions::perimeter_options()` returns default `WallDirection::CounterClockwise` when `wall_direction` is absent.
- `wall_direction: "ccw"` produces the same perimeter point order Ares emits today.
- `wall_direction: "cw"` reverses external contour wall point order and rectangular internal wall point order.
- Invalid `wall_direction` values return `SliceError::InvalidInput` at the perimeter option boundary.
- A pipeline/G-code regression proves the JSON option changes emitted `;PERIMETER:` / `;PRINT_PATH:` path order for a rectangular fixture.
- Rust source files touched by this slice stay below the repository 400 LOC split threshold.

## Files

- Modify `crates/ares-core/src/perimeters.rs` for `WallDirection`, `PerimeterOptions`, and path orientation.
- Modify `crates/ares-core/src/perimeters/tests.rs` for perimeter-level direction tests.
- Add `crates/ares-core/src/options/wall_direction.rs` for option parsing.
- Add `crates/ares-core/src/options/tests/wall_direction.rs` for parsing tests.
- Modify `crates/ares-core/src/options.rs` only to include the new module and call the parser from `perimeter_options()`.
- Modify `crates/ares-core/src/lib.rs` only to re-export `WallDirection` alongside the existing perimeter API.
- Modify `crates/ares-core/src/options/tests.rs` only to declare the new focused test module; it is already 399 LOC and must not exceed 400 LOC after this slice.
- Add `crates/ares-core/src/pipeline/tests/wall_direction.rs` for the G-code regression, and add only the module declaration to `crates/ares-core/src/pipeline/tests.rs`.

## Docs Impact

No architecture or roadmap documentation update is required for this narrow runtime consumption slice. The source-cited design document, implementation plan, and regression tests are the durable documentation for the behavior added here.
