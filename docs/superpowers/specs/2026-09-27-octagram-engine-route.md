# Octagram spiral routes through the ported Clipper engine

## Upstream and Rust boundaries

`FillPlanePath.cpp:129` clips every plane-path fill (including
`FillOctagramSpiral`) with `ClipperUtils::intersection_pl(polylines,
expolygon)` → `_clipper_pl_open` → the vendored Clipper 6 engine
(`deps_src/clipper/clipper.cpp`). Open-path results come from
`BuildResult2` (`:2801-2852`), which emits surviving open `OutRec`s in
allocation order — the order in which `CreateOutRec` first produced
output while the scanbeam descended (`:1668-1682`, `:1987-2020`).

Ares previously emulated that order with a geometric sort in
`fill/plane_path/classic_clip.rs` (max-Y desc, ±1-unit tie band, min-X
with a sign flip). The emulation's key has no upstream counterpart and
mis-ordered symmetric spiral islands (top_surface_pattern/octagramspiral
case diverged at layer 50).

## Change

`fill/plane_path.rs` now routes `OctagramSpiral` through
`intersection_open_polylines` like every other pattern — the ported
Clipper 6 state machine (`geometry/clipper`, fixed commit 8500fcd)
reproduces the OutRec creation order and orientation. `classic_clip.rs`
(+ tests) deleted; `-434` LOC.

Verified: the top_surface_pattern/octagramspiral seeded case now diffs only on the `; generated by`
header line.
