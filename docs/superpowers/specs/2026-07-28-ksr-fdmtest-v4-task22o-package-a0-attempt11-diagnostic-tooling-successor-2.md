The reviewer is read-only and evaluates:

1. `requirements_completeness`;
2. `logical_correctness`;
3. `boundary_cases`;
4. `code_quality`;
5. `test_coverage`;
6. `actual_execution_results`.

The reviewer must rehash all subjects immediately before verdict, verify the
complete runtime closure, confirm predecessor immutability and production
absence, and return a concrete repair list for any finding. The main thread
fixes only those findings, freezes a new exact snapshot, and returns it to the
same review task until `APPROVE`.

Only non-installer source and candidate-rendering findings may be repaired
through a new append-only source-review iteration. Any finding that requires
changing an installer-owned immutable file, focused approval, runtime-install
schema/transaction, installed runtime, or runtime contract after reservation
creation is terminal for this namespace and requires separately reviewed
successor roots.

No production failure packet, runtime ledger, source ledger, or successor
matrix execution is authorized before six-axis approval of the exact candidate
bytes.

## Approved-subject publication transaction

After six-axis approval, the failure packet, runtime ledger, and source ledger
are published through one qualification-publication transaction. Its evidence
paths are fixed:

```text
C:\a22or17-evi\diagnostic-tooling-successor-2\qualification-publication-reservation-v1.json
C:\a22or17-evi\diagnostic-tooling-successor-2\qualification-publication-terminal-receipt-v1.json
```

The publisher constructs its reservation only from the approved source-review
envelope, immutable manifest, exact argv/cwd/environment, and expected output
identities. It creates, flushes, and reads back the reservation before any
failure-capable subject validation or output write. It then validates every
approved input, publishes the three outputs in the fixed order failure packet,
runtime ledger, source ledger, by copying the approved candidate bytes exactly
without re-rendering, and recursively validates their complete DAG.

Only after complete DAG and post-state validation may it construct a passed
terminal state. Any validation, collision, write, flush, readback, or
post-validation failure constructs a failed terminal state. It writes exactly
one terminal receipt and then permits only independent read-only receipt
verification. The passed receipt additionally binds the exact matrix entrypoint
path/byte count/SHA-256, its fixed parent-identity argv contract, cwd, ordered
environment, and the three fixed output paths it authorizes. A matrix command
whose own identity or launch contract differs is unauthorized.

A reservation, any partial output, a failed receipt, or a missing terminal
receipt consumes the publication namespace and forbids the matrix. It is never
legal to complete missing outputs, overwrite failed bytes, or replay the
publisher. Only one independently valid passed publication receipt authorizes
the one matrix command.

## Post-matrix continuation

On a passed matrix receipt:

- publish one complete successor production binding;
- obtain the required independent tooling review and final envelope;
- preserve the existing complete iteration publication mapping;
- recursively validate source, runtime, tests, review, and failure subjects;
- bootstrap the Attempt-11 diagnostic reservation once;
- run the one Attempt-11 diagnostic exactly once;
- classify only from its complete durable receipt.

On a failed matrix receipt, missing terminal receipt, binding failure, review
failure, or diagnostic infrastructure failure, stop. Preserve all bytes and
start a separately reviewed recovery namespace. Do not rerun or repair in
place.

## Exit criteria

Successor 2 exits only when all of the following are true:

- predecessor evidence remains byte-exact and terminal;
- technical and governance reviewers approved identical successor documents;
- the failure packet is complete and create-once;
- a complete ordinary portable PowerShell runtime is installed and bound;
- focused RED/GREEN history proves the actual process-start boundary;
- all successor sources remain below 400 lines and pass syntax/compile checks;
- the same independent six-axis task approves the exact successor snapshot;
- one successor source ledger is published;
- exactly one successor matrix invocation yields one passed terminal receipt;
- no forbidden A0, OrcaSlicer, formal, claim, candidate, collector, or
  publication mutation occurred.

Only then may the main Attempt-11 diagnostic flow resume.
