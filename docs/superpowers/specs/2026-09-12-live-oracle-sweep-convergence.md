## Observable contract

Continuation of the OrcaSlicer v2.4.2 printer smoke program
(`docs/superpowers/specs/2026-08-27-orca-printer-smoke-option-parity.md`)
under the strict ordered-byte oracle
(`docs/superpowers/plans/2026-09-08-strict-output-oracle.md`). The live

both slicers and keeps `tests/parity/printer-smoke-summary.md` as the
tracked divergence inventory. Every fix slice must move printers to PASS
with no regressions, verified by a full fresh sweep before commit.

This wave's accepted slices:

1. **Vendor-branded generator lines** — presets that embed a branded
   `; generated by <vendor> <version> on <date> at <time>` line in custom
   start G-code (Creality K2 family) differ from Ares only in local-time
   identity; the oracle masks exactly that timestamp line shape, matching
   ARD-0023's generator identity/timestamp allowance.
2. **Truthful sweep statuses** — reference-producer failures are no longer
   reported as Ares errors: `ORCA_ERROR` (the upstream 2.4.2 binary itself
   crashed) and `VENDOR_INCOMPLETE` (the vendor tree lacks the machine's
   referenced default process preset) are distinct, still-failing statuses.
3. **Change-layer lift enforce gate** — upstream `change_layer`
   (`GCode.cpp:5690-5696`) increments `m_layer_index` before its retract,
   so `retract_lift_enforce` (`GCode.cpp:7678-7705`) evaluates at the new
   layer index; Ares defers the hop after the layer index advances and only
   strips the layer travel's z word when a hop was actually deferred
   (`m_need_change_layer_lift_z`, `GCode.cpp:7479-7482`).
