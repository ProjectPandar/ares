# Fixed generated-at header for Moonraker metadata discovery

## Source boundary

This is a Rust rewrite slice of OrcaSlicer `40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`'s automatic producer-line syntax, not a new slicing or statistics pipeline.

- [`GCode.cpp:4233–4242`](https://github.com/OrcaSlicer/OrcaSlicer/blob/40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19/src/libslic3r/GCode.cpp#L4233-L4242), `GCode::do_export`, suppresses the header for a `BTT_TFT` thumbnail list; otherwise it writes `HEADER_BLOCK_START` and `; generated by %s on %s\n`.
- [`utils.cpp:1515–1518`](https://github.com/OrcaSlicer/OrcaSlicer/blob/40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19/src/libslic3r/utils.cpp#L1515-L1518), `header_slic3r_generated()`, supplies the application name and release version.
- [`Time.hpp:35–37`](https://github.com/OrcaSlicer/OrcaSlicer/blob/40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19/src/libslic3r/Time.hpp#L35-L37), `Utils::local_timestamp()`, obtains Native's local time. `Time.cpp:26–38` defines the G-code form `%Y-%m-%d at %T`. The syntax is included; Native's clock lookup is deliberately not ported.

Moonraker's independent consumer boundary is [`metadata.py::PrusaSlicer.identify`, lines 433–458](https://github.com/Arksine/moonraker/blob/4ba6fd228f264564f6613197fd9abb18ec068cf4/moonraker/components/file_manager/metadata.py#L433-L458). Its generic fork expression requires `; generated by (.+?) on \d{4}-\d{2}-\d{2} at \d{2}:\d{2}:\d{2}`. An undated Ares line selects `UnknownSlicer`, which does not extract the duration and filament fields. Ares does not need to impersonate OrcaSlicer or change its existing statistics comments.

## Producer-line contract

Both Rust emitters write exactly these ASCII bytes, including the terminal LF:

```gcode
; generated by Ares 2.5.0 on 1980-01-01 at 00:00:00
```

`1980-01-01 at 00:00:00` is a fixed DOS-epoch marker, not the export's creation time. It never depends on the system clock, time zone, process, worker, browser, caller metadata or options. There is no alternate undated line, optional suffix, duplicate compatibility line or new configuration option.

This replaces the undated-Ares requirement in [version-identity-250.md](version-identity-250.md) and the automatic-header deletion/rejection policy in [ARD-0095](ard-0095-reproducible-generation-inputs.md). The release identity remains exactly Ares `2.5.0`.

`GenerationMetadata` remains an explicit deterministic input for the existing template language. Its default remains Unix epoch zero (`1970-01-01 00:00:00`); its calendar fields and `{timestamp}`, `{year}`, `{month}`, `{day}`, `{hour}`, `{minute}`, `{second}` behavior are unchanged. Seed zero and existing ZIP DOS-epoch defaults are unchanged. Do not derive the producer marker from `GenerationMetadata`, change its default to 1980, read a clock, add time arguments or modify CLI/WASM calls.

BBL and ordinary project exports that already emit a header receive the same fixed Ares line, without changes to their other header/statistics policies.

## Comparison boundary

Ares acceptance is exactly one complete anchored line:

```text
(?m)^; generated by Ares 2\.5\.0 on 1980-01-01 at 00:00:00$
```

Do not use numeric date/time patterns, optional timestamps or a time-normalization pass for the Ares producer. An undated line, any other date/time, wrong brand/version, duplicate line, unanchored match or extra suffix must fail the existing generator-only comparison contracts.

The Native rule remains exactly OrcaSlicer `2.5.0` with its existing zero-padded timestamp shape. After each side passes its own identity rule, the existing complete-producer sentinel mapping may erase the permitted producer-line difference. It must not make a variable Ares timestamp acceptable. Existing vendor-branded timestamp handling stays unchanged: vendor brand/version bytes remain protected.

Compare the complete remaining ordered byte streams. Do not normalize CRLF/LF, whitespace, motion, statistics, configuration, comments or any additional field. Processor-observer substitutions replace only the validated fixed Ares producer line with the already-defined Native observer identity; they do not rewrite exported files or footer values.
