# Preserve the Z travel decision when cancelling a lift

OrcaSlicer v2.5.0 `GCodeWriter::will_move_z` (`GCodeWriter.cpp:1279–1292`) uses the exact lifted interval `[writer Z − lift, writer Z]` while a lift is active. It uses an epsilon for an unlifted writer instead. `GCodeWriter::travel_to_xyz` (`GCodeWriter.cpp:1096–1139`) decides whether to use the XY-only branch before resetting the lift; if the move requires Z and the writer position is unclear, it emits XY followed by Z. The direct approach from `GCode::travel_to` (`GCode.cpp:10637–10651`) supplies the nominal Z. The distinct forced Z synchronization after travel in `GCode::_extrude_piece` (`GCode.cpp:9361–9383`) is not a substitute for either approach move.

Port the branch ordering in `motion/path/start_travel/approach/move_emit.rs`. In the ordinary fallback for an unclear writer position, a just-cancelled lift must retain the decision to emit Z. Do not consult the unlifted epsilon as though the lift had been absent when the travel was planned. The exact upper endpoint remains inside the lifted interval. The existing approach dispatcher remains the Rust port boundary; toolchange state, lift interval math, slope routes, nominal Z synchronization and the cooling pass are unchanged.

Exercise the normal slice interface on a synthetic tower-off, two-filament project with a change template that reports Z at the rounded third layer height. Compare to the pinned OrcaSlicer output. At a 0.2 mm layer height the nominal third height is one representable double above the parsed `0.6`; the preceding lift and the unclear writer position make both approach commands observable. The layer cooling calculation must receive the actual emitted travel, not a corrected feedrate.
