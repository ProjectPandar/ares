# Top-level headless 3MF export from STL

## Upstream boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`) declares the top-level `--export-3mf` action in `src/libslic3r/PrintConfig.cpp:12734–12739`. `CLI::run` uses `LoadModel | AddDefaultInstances` for STL input (`src/OrcaSlicer.cpp:1741–1758`) and puts ordinary objects on the bed (`1968–1978`). `Model::read_from_file` routes to `load_stl` and adds the default instance (`src/libslic3r/Model.cpp:318–356,506–508`; `Format/STL.cpp:18–40`). `CLI::run` loads any supplied preset files and applies the result over `FullPrintConfig` (`OrcaSlicer.cpp:2280–2470,4252–4259`); optional files are not a requirement to produce an unsliced archive.

- **Convert, then arrange.** `CLI::run` applies `--convert-unit` before placement (`4961–4972`). The `Model` methods use solid volume and check metres before inches (`Model.cpp:978–1041,2625–2646`); the object/volume conversion preserves the provenance of the original STL (`1990–1998,3116–3125`). Arrangement defaults on for STL; `--arrange 0` disables it and `--arrange 1` forces it (`OrcaSlicer.cpp:1545,1768,5051–5065,5343–5350`). Arrangement consumes the converted geometry (`5536,6011–6012`); the resulting instances belong to the rebuilt plates (`6091–6093,6263`).
- **Slice only if requested.** The export option records the destination (`6423–6425`). `--slice 0` selects all plates; a positive selection chooses a one-based plate (`6441–6457,6522–6531`). The slice applies the model to the print, validates, processes and exports G-code (`6986,7009,7099–7114,7184–7193,7238`). `PartPlateList::store_to_3mf_structure` collects the completed plate result (`src/slic3r/GUI/PartPlate.cpp:8459–8495`). Without `--outputdir` the G-code is temporary, not published next to the archive (`OrcaSlicer.cpp:7184–7186`).
- **One archive writer.** `CLI::run` reaches `CLI::export_project` whether or not it sliced (`7340–7345,8081–8086`). `CLI::export_project` fills `StoreParams` and calls `store_bbs_3mf` with `Silence | WithGcode | SplitModel | UseLoadedId | ShareMesh` in both cases (`8387–8405`). `_BBS_3MF_Exporter::_save_model_to_file` writes model and config members and only includes G-code and its checksum for valid existing sliced data (`src/libslic3r/Format/bbs_3mf.cpp:6327–6347,6418,6793–6836,6854–6855,9005–9025,9723–9732`). Its model settings include the converted part's `source_in_meters` or `source_in_inches` when applicable (`438–439,8388–8392`). `WithGcode` does not cause slicing.

## Scope and Rust destination

Accept `ares [--load-settings FILE[;FILE]] [--arrange 0|1] [--convert-unit] [--slice N] --export-3mf OUT INPUT.stl`. Without `--slice`, export one ordinary STL as an unsliced FFF project using default, partial (such as one machine file), or already-supported complete explicit presets. With `--slice N`, export that same resolved model/configuration and its completed plate data; use valid presets, including the existing direct STL and arranged multiple STL sliced shapes. The sliced archive must include the completed plate members and must not be published on input or slicing failure. A bare default Marlin slice can fail independently at `Print::validate` (`src/libslic3r/Print.cpp:2748–2766`); reproducing that validation gap is not part of this change.

- `ares-cli/src/{args.rs,main.rs,export_3mf.rs}` owns path resolution, argument validation, and dispatch. The top-level export route accepts `--slice` without requiring `--outputdir` when an archive destination is already supplied; preserve the output-directory requirement for the standalone G-code action. Route STL and saved-project inputs to their respective core adapters. Preserve existing output/error contracts for supported subpaths. Do not introduce an intermediate on-disk project or a second invocation of the slicer.
- Reuse STL import and transformation (`ares_core::ImportedStl::infer_unit` / `convert_to_millimeters`), the existing direct STL arrangement and core preset composition (`ares-cli/src/direct_stl`, `ares-core/src/profiles/entry/load_settings.rs`, `ares-core/src/project_slice`). Placement and slicing consume the same converted model; writing serializes its geometry, source provenance, placement and effective configuration rather than reopening the original STL. Use the existing no-preset and partial-preset direct STL selection machinery, not an export-only set of invented defaults. The old complete-selection guard is a boundary for the saved-project preset export, not STL admission.
- Keep archive assembly in `ares-core/src/project/export.rs` and its `geometry`, `project_settings` and `xml` modules. The [saved-project explicit-preset export](cli-export-3mf-saved-presets.md) overlaps here: preserve its embedded config overlay, input admission, saved object/instance identity and plate metadata. The web project save also uses this writer: preserve its unsliced `SceneLayout`, per-instance transforms, metadata and secure settings path. Neither path should receive fresh-STL arrangement/defaults. Preserve existing single/multi-plate sliced member and checksum order, STL numeric handling and the shared transform precision. Integrate the fresh-STL data at the existing writer boundary rather than replacing the other callers or forking the writer.

Not included: general STL/3MF mixtures, new unsliced multi-STL layouts, new saved-project slicing shapes or preset combinations, conversion of saved 3MF, STL export unit changes, arbitrary rotations/orientation, minimum saves, load/export slice caches, or new auxiliary members. Preserve the supported no-orientation option. This is the STL path through `Model` and `StoreParams`, not a new project pipeline.

## Remove the temporary export spelling

Remove only `--export-3mf` from the `ares slice` subcommand once its supported uses have moved. Native treats a positional `slice` as input, not an action. All currently supported `slice … --export-3mf` export operations have equivalent Native top-level argv. Reuse the existing saved-project sliced handler from the top-level route to migrate the existing 3MF cases; this is dispatch only, not expanded 3MF geometry or settings support. Do not retain a second spelling or change unrelated uses of `ares slice`.
