# Producer identification for Native test inputs

OrcaSlicer v2.5.0 recognizes the `generated by OrcaSlicer` signature via substring matching (`src/libslic3r/GCode/GCodeProcessor.cpp:2752–2753,5164–5174`). Its file processor detects the producer and then loads the embedded configuration before parsing commands (`:3860–3933`). That configuration selects the vendor and hence the reserved tag table (`GCodeProcessor.hpp:657`); roles, wipes, markers and layer changes are dispatched in `GCodeProcessor.cpp:4423–4435,4484–4493,4601–4695`. Custom overview depends on the resulting layers, just as tagged marker timing depends on the resulting vertex sequence.

The tagged marker adapter (`tests/support/marker_time.rs`) and custom overview fixture runner (`tools/chain-probe/custom-gcode-overview-fixtures.mjs`) prepare Native inputs from the actual Ares G-code. Match exactly one full Ares producer header of the form `; generated by Ares <version> on <date> at <time>`, without pinning the Ares release. The match must be the second line; absence, malformed header or multiple producer headers fails before invoking Native. Replace only the producer name and version with `OrcaSlicer 2.5.0`, preserving the timestamp, line ending and all other input bytes. Keep the original Ares artifact.

Regression coverage examines the tagged input artifact generated from a real slice and runs the existing custom overview cases against Native. Keep the tagged double-run determinism check and every ID, duration and elapsed comparison, as well as the custom overview comparators. This change does not port a processor or viewer kernel, alter exported product G-code, or change any expected values; report any remaining parity mismatch separately.
