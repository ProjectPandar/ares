# Stock signal audit: all twelve cases docs only (2026-10-09)

## Decision and source boundary

Decision: **all twelve cases are docs only; no new runtime
test is admitted**. The proposed three-case admission was first reduced after
MyToolChanger 0.8 crashed, then withdrawn entirely after XL 5T 0.6 crashed.
Even fail-closed directed tests would randomly turn unrelated gates red
because the Native producer itself crashes nondeterministically. No retry,
crash skip, assertion relaxation, preset repair or crash emulation is introduced.
The existing stock selector, runner, cache recipe and production code are unchanged.

The withdrawn proposal would have exercised the existing source-cited
`libslic3r` rewrite, not a new
Ares pipeline: upstream `PresetBundle.cpp` preset/full-config ownership,
`Print.cpp` print processing and `GCode.cpp` complete export; Rust owners
remain `ares-core::profiles`, project loading and `project_slice::gcode_emit`.
The CLI/stock runner is an adapter and a temporary compatibility shell around
those upstream concepts, not an independent slicing implementation.

Measurement contract: unchanged stock selector/inheritance flattening, existing export
compatibility fill and runtime Native export recipe, the same exported 3MF
bytes for both consumers, and complete G-code equality. Only the entire
`; generated by` line is excluded; no clock-field, footer, config, executable,
ordering or numeric exemptions. Native signal/nonzero exit fails closed:
**no retry and no crash skip**. Missing optional Native uses the existing
shared visible SKIP; required Native absence fails closed before artifact-root
access. No Native-generated 3MF/G-code/result products are committed.
The withdrawn tests cited vendor sources and used the existing stock runner;
no parallel selector/cache/registry or production fix was introduced.
No new test from this audit remains.

Deferred: all other historical signals, crash emulation, Native argv interface
expansion, preset repair and any new production rewrite behavior. The initial proposed admission was
based on three measured runs, not a claim that Native can never crash; later
failures invalidate that proposed admission without rewriting the old observations.

## Docs-only signals and Cubicon reconstruction

Initial MyToolChanger 0.2, Creator 5 Pro 0.4, and XL 5T 0.25 primary slices
were SIGSEGV with no G-code. Fresh stack owner remains **unknown** because the
separately instrumented debugger runs exited normally. No
further probes or tests were run. The three intermittent SIG11 rows above also remain
docs only; successful sibling attempts do not erase their failures.

Cubicon xCeler-I, xCeler-Mini and xCeler-Plus 0.4 all abort during Native CLI
filament argv loading, before 3MF export or slicing. Existing saved SIGABRT
backtraces identify `ConfigOptionVector<std::string>::set_at` at
`libslic3r/Config.hpp:445`, called by `Slic3r::CLI::run` at
`OrcaSlicer.cpp:3301`, with captured `i=0`, `j=0`, and this/rhs pointer arguments.
The exception is `ConfigOptionVector::set_at(): Assigning from an empty vector`.

The key is reconstructed as **`default_filament_colour`** from the same inputs
and owning source, **not read from a saved live `opt_key` local**:

1. Each selected filament JSON has that unique bare-empty string field (`""`),
   with no empty JSON array. `PrintConfig.cpp:2447` defines it as `coStrings`.
2. `Config.cpp:146-149`, `unescape_strings_cstyle`, returns immediately for a
   bare-empty serialization without pushing a string. This differs from the
   one-element empty-string vector default (`ConfigOptionStrings{""}`).
3. The CLI's vector skip list at `OrcaSlicer.cpp:3278` does not exclude this key.
   It reaches the ordinary non-variant vector assignment at 3301:
   `opt_vec_dst->set_at(opt_vec_src, filament_index - 1, 0)`.
4. `Config.hpp:439-445` throws when the same-type source vector is empty,
   matching the captured string-vector specialization and exception.

Saved logs contain backtrace arguments, not `opt_key`/`values` local dumps;
those sessions have exited. Uncaptured locals cannot be recovered from these
logs. No new gdb probe was run.

**Ares behavior: N/A**. Native crashed at the
`--load-settings`/`--load-filaments` argv-loading interface and produced no 3MF;
Ares CLI has no corresponding interface surface. Neither literal unsupported
