# CLI model assembly

Upstream: OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`).

## Included

- `ares slice --assemble --arrange 0` with positional STL files or a single 3MF. Use the first 3MF's embedded settings or the existing `--load-settings`/`--load-filaments` path as on nonassembly input. The new instance is not the 3MF build placement. STL source coordinates and 3MF component transforms are preserved. `--load-filament-ids` supplies positional STL object filament assignments when `--load-filaments` is supplied.
- `ares slice --load-assemble-list list.json`, with no positional inputs or transforms. `plates` has 1–36 entries with required `plate_name`, `need_arrange: false`, and nonempty `objects`. Object `path` (relative to working directory), positive `count`, and nonempty `filaments` are required. STL paths are case insensitive by extension. Optional `pos_x/y/z` and `assemble_index` default to zero. Repeat entries as in `construct_assemble_list`: copies inherit the first translation and apply the selected additional translation; the X selector is shared across the three position vectors. Reject any selector that would index outside a vector. A positive index merges only within its own plate, creating `assemble_N` on first occurrence, with parts in encounter order. Nonpositive indices create independent `stem_N` objects. One list plate is selected via the existing `--plate` adapter option (default first); the byte model retains all plates. Single logical filament per list plate is included, including ID 0 (default).
- The filesystem adapter supplies named byte buffers and preset files, writes G-code, and translates structured failures to process status and `result.json`. `ares-core` owns manifest parsing, volume/instance construction and the existing project-slice seam. No filesystem or serialized intermediate project in core. The existing project model is the Rust destination for `Model`, `ModelObject`, `ModelVolume` and `PlateData`; the CLI remains the adapter, not a second assembly pipeline.

## Deferred and failure protocol

- Native-invalid combinations preserve Native status and diagnostic: no input to positional assembly (`-2`, `Invalid params: --assemble needs at least one input model.`), list plus positional inputs or any transform (`-2`, `load_assemble_list should not be used with input model files to load and should not be sued with transforms`), positional assembly plus `--clone-objects` (`-2`, following Native's clone list size and preset checks). `--assemble-list` is rejected as an unknown option, not an alias.
- Missing list or source file is `-3` (`The input files to the slicer are not found.`); malformed manifest or invalid required values are `-5` (`The input preset file is invalid and can not be parsed.`); unreadable geometry is `-6` (`The input model file to the slicer can not be parsed.`). An existing 3MF as a *list member* is already unsupported by Native (`-2`, `unsupported file …, plate index …, object index …`).
- Do not silently fall back for valid Native features outside this slice: automatic placement (including `need_arrange: true`), other assembly transforms, multi-archive positional import, colored OBJ list members, list `plate_params`/`print_params`/`height_ranges`/`assembled_params`, or list plates with multiple filament IDs and their wipe tower setup. These combinations return `-2` and the Native `Invalid parameters to the slicer.` result string, plus a specific unsupported-feature diagnostic. Native may succeed on these inputs; there can be no matching Native failure for a valid deferred operation. Native-only actions such as project export are not added to the existing slice command.
