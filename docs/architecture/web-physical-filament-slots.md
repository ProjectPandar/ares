# Physical filament slots in Prepare

## OrcaSlicer boundary

The reference is OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`). A project slot is a 1-based position in the ordered palette, not a preset name or a printer head. Distinct slots can use the same preset; an empty imported preset position still occupies its index. A virtual (mixed) slot is a separate kind of position and follows the physical slots.

- `src/libslic3r/PresetBundle.cpp:4328–4372` (`set_num_filaments`) extends the selection by copying the last preset when there is one, sizes the project colour/map/mixed vectors, and initializes the new colour, multicolour and type. `:4375–4465` (`update_num_filaments`) erases the selected position and updates the edited preset if its selection disappeared. `:4467–4495` distinguishes colour-backed slot count from a preset list padded for a printer. `src/libslic3r/PrintConfig.cpp:11446–11462` owns mixed metadata sizing and `src/libslic3r/FilamentMixer.cpp:560–584` owns component-ID deletion.
- `PresetBundle.cpp:8598–8671` (`update_multi_material_filament_presets`) owns the minimum selection count and flush resize: one directed square table per nozzle, a multiplier per nozzle and load/unload volume pairs. Deletion skips the removed row and column for each nozzle but truncates the legacy volume vector at the end. `src/libslic3r/PrintConfig.cpp:8267–8295` defines the stored defaults.
- `src/libslic3r/Model.cpp:2744–2790,4050–4075` and `src/libslic3r/TriangleSelector.cpp:1876–1887,2062ff` own paint-state cleanup and shifting without changing the facet splits. Project and plate option storage, model assignments, and `CustomGCode::Info`/`Item` in `src/libslic3r/CustomGCode.hpp` are the core data this operation updates; the desktop invokes those changes from Prepare.

## Project operation

- **Add.** Start from the composed project's physical and virtual slots. Insert a new physical position after the last physical one, initialize its preset and colour using the desktop Add rules, and shift the existing virtual positions. Existing preset overrides move with their slots. Use the existing `FlushVolCalc` rewrite (`ares-core/src/options/flush_volume` and `options/flush_matrix.rs`) for the desktop's add-time initialization of transitions to and from the new physical slot (`Plater.cpp:6029,6988–7130`), not a browser approximation or a recompute of unrelated physical transitions. A standalone flushing editor and settings for recomputing other rows are separate.
- **Delete or merge.** Remove just the source physical slot; neither action replaces the destination's preset or changes library installation. A surviving slot strictly above the removed position shifts down once. For object/part `extruder`, references to the deleted slot go to slot 1 on plain deletion or to the replacement's post-delete ID on merge. Absent part overrides continue to inherit. For MMU paint the deleted state clears to unpainted on plain deletion and maps to the replacement on merge; retain unaffected leaves and subdivision. Object, part and project `support_filament`/`support_interface_filament` clear a match and shift higher references even during merge (the desktop does not redirect those selectors). Keep default/auto sentinels distinct from real slots. For an imported mix, follow `FilamentMixer.cpp:560–584`: use the deleted-component zero sentinel, keep it in its ratio position, and decrement higher component IDs; merging does not silently rebuild the mix.
- **Existing plate state.** Use the slot transformation on every affected plate, not just the active plate. Erase deleted entries from explicit first-layer and other-layer orders and decrement higher IDs; keep Auto, layer ranges and unrelated plate data. Move any per-slot map entries with the slot; a map *value* denoting a nozzle or volume type is not a slot ID. For custom G-code, touch only typed `ToolChange` items: remove matching ticks on Delete or redirect them on Merge; retain their order, Z and other tick types and payloads.
- **Validation and editing.** Check source and target in the current palette, reject self-merge, count changes on fixed-head printers, last-physical removal and adds beyond the supported limit. A rejected operation leaves the session unchanged. Edit binds the existing preset editor to the selected physical position, including project-derived presets and repeated names; an empty position is never redirected to a different slot. Relay settings changes through the existing preset composition by slot. Opening/cancelling Edit is not a project edit. Preserve nonphysical merge targets where the Native menu exposes them; when an imported target uses the source as a component, preserve the desktop warn/cancel path before committing (`Plater.cpp:5897–5929`). No virtual row CRUD is introduced here.

## Architecture decision: keep references attached to their slots

**Context.** On physical insertion before a virtual tail, the desktop moves some references but appends to plate maps and orders, leaves several IDs unchanged, and does not rotate the flush tables (`Plater.cpp:5940–6029`, `PartPlate.cpp:5680–5722,5901–5928`, `PresetBundle.cpp:8633–8669`). Its tick merge also uses the `remove_if` tail and converts the replacement ID a second time (`Plater.cpp:21504–21519`). Following those paths literally can change a material assignment merely because its index changed.

**Decision (user, 2026-11-23).** Inserting a physical slot moves every reference to each surviving slot along with its per-slot data, including both axes of every flush table. Objects and parts stay on the same material. Shift support selectors, explicit orders and typed tool-change references, and add the new slot to explicit orders. On delete/merge, apply the change once to each original tick. Unrelated tick types and payloads are unchanged.

**Verification.** Assert preservation directly at the project interface, not with a Native byte comparison for these deliberate differences. Separately, do not port any out-of-bounds access from the Native stride calculation: use the actual per-nozzle bounds and cover them with an asymmetric multi-nozzle invariant test. The existing Native comparator stays unchanged for matching routes.

## Rust and adapter destinations

1. **Core slot data:** `crates/ares-core/src/profiles/filament_slots.rs` (`FilamentSlotState`) owns ordered project slot data and sizing. Reuse the project-open normalization slice's shared core `FilamentSlotState::resize_flush` sizing implementation; the final name and interface follow that slice's accepted version, not its proposed signature. The project-open slice owns defaults, missing option handling, and the shared sizing rules. This slice owns the interactive positional insert/delete transforms and calls the shared sizing code; do not copy the flush rebuild or call an archive-open routine as an editing command. Existing catalog normalization in `profiles/catalog/filament_slots.rs` remains the adapter for preset/printer selection, not a second slot editor.
2. **Core project mutation:** extend `PlaterSession` (`crates/ares-core/src/plater`) with slot queries/capabilities and an atomic Add/Delete/Merge operation. The operation receives slot IDs, not parallel option arrays; it returns the authoritative ordered slot view. Carry the change through `plater/edits.rs`, `plater/snapshot.rs`, `project/domain/plater_edits.rs`, and existing project plate config, facet annotation, and custom G-code modules. Slicing and Save Project must see the same composed slot state and remapped model/plates as the visible scene, even where slicing rebuilds from the original bytes. Undo/redo restores both sides of the operation together. Use the existing project writer, not a separate export path.
3. **WASM and web:** expose the slot view and operations through `crates/ares-wasm/src/plater` and `web/packages/ares-wasm-js/src/{protocol,platerEdit,platerSession}.ts`. `web/app/src/sidebar/FilamentSection.tsx` uses the view to render count controls and row actions and reuses the existing preset editor. `FilamentDialog.tsx` still manages the installed library. Replace the sidebar's selection-array bookkeeping for these actions with the returned core state; do not splice or remap project state in React. Refresh Prepare assignment menus, object-list cells, scene colours and the next slice/preview from the same state.

The Prepare Change Filament routes (context menu and inline cell) continue to set assignment only, including their existing Default behavior. Slot topology changes remap their stored results; they do not change menu eligibility. The saved-project CLI `--load-filaments` sparse overlay continues to apply files to their original positions. Do not use it as a slot-count API or compact a leading empty position to build the sidebar. Leave ingestion of untouched projects and CLI profile-file composition unchanged.

Deferred: authoring mixed or decomposed colours, palette/colour editing, manual flush and grouping controls, plate order and tick authoring, painting tools, AMS sync, and converting preview-only G-code archives into editable projects. Their already-imported slot references are not deferred when editing topology.
