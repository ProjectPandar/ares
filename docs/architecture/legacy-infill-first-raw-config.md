# Preserve the infill-first boolean derived from legacy process presets

## Upstream contract

Source: OrcaSlicer v2.5.0, `40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`.

- `src/libslic3r/PrintConfig.cpp:2779–2784` defines `is_infill_first` as `coBool`, default false. For **authored** boolean strings, `ConfigBase::load_from_json` calls `set_deserialize` (`Config.cpp:985–987`); legal arrays are joined and dispatched there too (`:1008–1058`). `ConfigOptionBool::deserialize` consumes the first comma-delimited token, trims it, and accepts only `"0"` or `"1"` (`Config.hpp:1927–1947`). `serialize` writes `"0"` or `"1"` (`:1922–1925`). Forward substitution is a separate path (`Config.cpp:686–700`, `Config.hpp:118–121`); in particular `"true"` is not a valid coBool token or a true-valued substitution. Bare JSON booleans are not dispatched as preset wire text (`Config.cpp:1060–1063`).
- For **derived** booleans, the JSON loader sees `wall_infill_order` equal to `infill/outer wall/inner wall` or `infill/inner wall/outer wall`, schedules `is_infill_first`, then sets `ConfigOptionBool::value = true` after reading the JSON (`Config.cpp:996–1005,1072–1075`). The internal `"true"` marker in that C++ function is never parsed as coBool. The derived write wins over an explicit false in the same document, before the document is applied over its parents.
- Native's installed path is `PresetBundle::load_presets` → `load_system_presets_from_json` → `load_vendor_configs_from_json` (`PresetBundle.cpp:881–894,3458–3462,8124–8134`) → `read_vendor` using `ConfigBase::load_from_json` for each subfile (`:8424–8434,8507–8516`). Each parsed config overlays its parent/default and includes before variant completion (`:7797–7848`). The analogous user collection loader calls `load_from_json` in `Preset.cpp:1878–1889`. Native CLI `--load-settings` also goes through `load_config_file` → `load_from_json` → `resolve_preset` (`OrcaSlicer.cpp:2205–2239`).

## Stock inputs and Ares destination

`resources/profiles/Creality/machine/Creality Ender-3 0.4 nozzle.json:11` names `0.20mm Standard @Creality Ender3` as its default process. That process and its parents (`fdm_process_creality_common` → `fdm_process_common`) omit `is_infill_first`; the process's `wall_infill_order` is `inner wall/outer wall/infill` (line 27), so its effective source default is false (`"0"` on write). The failing **vendor collection** also loads the instantiated `0.20mm Standard @Creality Sermoon V1` (`Creality.json:998–999`), whose stock process file uses `"wall_infill_order": "infill/inner wall/outer wall"` (line 104), **not** an authored `"is_infill_first": "true"`. Native derives true (`"1"` on write). The same trigger is present in two other stock Sermoon V1 process files. Installing the Ender-3 brings in the Creality catalog, not just the selected printer's process.

Browser project import (`web/app/src/state/actions.ts::importFile`) calls WASM `create_plater_session_with_profiles` and `ares_core::PlaterSession::load_with_profiles`. Installed preset loading similarly calls core `load_preset_bundle`. `profiles/project_selection/loaded.rs::LoadedCatalog::collection` materializes all selectable process records. In `profiles/project_selection/collection.rs::load_config` each layer calls `ProjectSettingsRaw::handle_legacy`, then the merged config reaches `profiles/preset_normalization.rs::extend_default_config_length` → `options/json_deserialize.rs::deserialize_preset_config` → `options/json_deserialize/scalar.rs::normalize`. `options/legacy/token.rs::handle_legacy_derived` currently supplies the marker `"true"`, which `project/raw_settings.rs::handle_legacy` inserts as raw option text. The strict scalar decoder correctly rejects that marker. This is a producer bug, not missing support for a stock coBool spelling. The project settings builder already applies a derived `OrcaBool(true)`. The separate `SliceOptions` Serde path (`options/legacy.rs::normalize_legacy_options`) is public and is also used for CLI STL `--options`, the WASM `slice_stl` entry, and preset normalization. Its normalized option map must likewise apply the derived typed boolean after explicit settings.

The CLI does not load the entire vendor collection merely by opening a project. It **is exposed for `--load-settings` inputs that take the same legacy-derived path**: `profiles/load_settings.rs::compose_with_project` admits and composes preset documents; `profiles/catalog/compose.rs::merge` calls `ProjectSettingsRaw::handle_legacy` on authored layers. On a 3MF the composed raw values are read again by `project/domain/profile_input/three_mf.rs` via `deserialize_config_values`, which shares the same scalar decoder. A CLI 3MF with a load-settings process containing the Sermoon spelling is the focused repro to confirm before changing code; a default Ender-3 file with no trigger is not a CLI repro.

## Scope

Apply the derived value after that document's explicit fields in both normalization paths, preserving layer precedence. Write true as `"1"` in the raw preset config and as a JSON boolean in `SliceOptions`. The existing raw-config map is the compatibility representation for a parsed `DynamicPrintConfig`. Keep the strict `ConfigOptionBool` rewrite, caller overrides, vectors, forward substitution, adapter/UI code, preset admission and legacy wall-sequence rewriting unchanged. Do not add an `is_infill_first` exception to boolean parsing or substitute an internally derived true to false.
