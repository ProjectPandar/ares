# Multiple objects and parts in sliced 3MF export

## Native boundary

Port the split-model representation of `_BBS_3MF_Exporter` in OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`), `src/libslic3r/Format/bbs_3mf.cpp`:

- `_add_model_file_to_archive` (7328–7444, 7468–7496) assigns consecutive resource IDs in model order: the volumes of an object each use an ID, then the root component object uses the next ID. It writes `3D/Objects/<name>_<backup-id>.model` per object; `Model::get_object_backup_id` (`src/libslic3r/Model.cpp:753–761`) assigns the one-based backup IDs in traversal order for freshly imported objects. The root model holds the component objects and build items, and the model relationship file lists each component file. This is not one file per volume.
- `_add_mesh_to_object_stream` (7647–7711) writes one indexed mesh resource per volume in the component file, with untransformed local vertices. `_add_object_components_to_stream` (7527–7569) writes a component per volume with its resource ID, target path, and local transform (three rows of four columns, column-major). The mesh and component UUID prefixes encode the backup ID in the high 16 bits and the zero-based volume index in the low 16 bits. `_add_build_to_model_stream` (7571–7618) references the root component resource and writes the instance transform separately.
- `_add_model_config_file_to_archive` (8306–8416, 8576–8608) writes object and part names and configuration, one `normal_part` per volume, local-times-source matrix in row-major order, source bookkeeping and mesh statistics. The plate instance records reference the root resource IDs and use the loaded identify ID when available. Part settings use the same resource IDs as the components, not the source volume indices.
- `CLI::export_project` (`src/OrcaSlicer.cpp:8011–8025`) emits one first-layer bounding box per `PrintObject`, using its `ObjectBase` ID; one object with several volumes still has a single box. The plate bounds merge the individual boxes. The saved-input allocation sequence in [Sliced 3MF export](cli-export-3mf-sliced.md#bounding-box-object-identity) counts every imported volume before allocating the consecutive `PrintObject` IDs. `_add_slice_info_config_file_to_archive` (8816–8872) instead iterates the saved plate instances and uses their identify IDs and names, not the bounding-box IDs.

## Rust boundary and scope

Extend `ares-core::project::export`'s saved reader and shared writer to carry objects with ordered parts instead of a single mesh. Capture per-object names, bounds, area and layer heights at the existing sliced archive boundary in `project_slice::gcode_emit`, from the print that emitted the archived G-code. Keep the CLI's static saved-input ObjectID sequence and count objects, instances and parts; do not add IDs to the slicer's process state. The previous single-mesh writer is a compatibility shell for the same upstream split-model writer, not an alternative package format.

Support a headless, unsliced saved project with one plate, one printable instance per object, ordinary model parts and the existing single-nozzle, single-filament, layer-wise settings. First extend multiple objects with one part each, then multiple parts within an object, including a translated part and its corresponding matrix. Existing unsliced export and single-object sliced export retain their behavior. Multiple instances per object, negative volumes, modifiers, support enforcers/blockers, painting, advanced project assets, and other deferred inputs in the preceding slice are not added here.

## Verification

Exercise `--slice 1 --export-3mf` with the standard CLI parity harness and synthetic saved projects: two objects with one part each, then two objects with three total parts. Compare the whole archive against live Native in official and seeded modes using the existing sliced-package comparator, including checksums of each producer's raw G-code and the existing banner normalization. Check that no standalone G-code is published. Retain a rejection case for out-of-scope input. Compare the affected CLI/3MF/export cases against the base in both modes.

`ObjectToObjectDataMap` is keyed by `ModelObject const*` (`bbs_3mf.cpp:6218`), so its traversal order in `model_settings.config` (8306) depends on addresses rather than model order. Cold starts on identical saved inputs produced both top-level `<object>` orders. Ares emits objects in model order. For all multi-object sliced comparisons the top-level object records of this member are matched by ID, with identical record counts and byte-identical records, including their ordered parts and metadata. No other XML element or archive member order is normalized.
