# Native CLI binary STL export and exact mesh cleanup

## Source boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`) declares Boolean `export_stl`, path-valued `export_stls` and Boolean `repair` in `src/libslic3r/PrintConfig.cpp:12757–12766,12978–12982`. `Config.cpp:277,1812–1850,1900–1909` defines dashed names, bare Booleans and equals values. `src/OrcaSlicer.cpp:5246–5256` requests `ModelVolume::repair(true, …)` before the actions at `6398–6413`. Both actions iterate objects and call binary `store_stl` (`8333–8368`), despite the singular action's help. `8440–8495` supplies the 1-based `obj_<index>_<name>` basename, appends a case-sensitive `.stl` when absent, and uses either `<outputdir>/stl` (default `stl`) or the explicit plural directory.

`src/libslic3r/Format/STL.cpp:43–57` exports `ModelObject::mesh`, not a whole-model merge. `Model.cpp:805–812,1675–1703` adds missing instances and folds model-part meshes in instance order. `TriangleMesh.cpp:241–244,1793–1826` supplies an empty label to `its_write_stl_binary`: all 80 header bytes are zero, followed by the little-endian face count and one 50-byte record per face. Each record uses the normalized `(v1 − v0) × (v2 − v1)`, the three ordered f32 vertices, and a zero two-byte attribute. Neither the header nor signed zeroes are masked.

There are **two different repair paths**. STL import always calls `ReadSTLFile(…, true, …)` at `Format/STL.cpp:18–39`. `TriangleMesh.cpp:95–200,223–233` calls the ADMesh exact-neighbor, normal and volume operations and builds shared vertices (`deps_src/admesh/connect.cpp:432`, `normals.cpp:115`, `util.cpp:290`, `shared.cpp:35`). The generic `stl_repair` (`util.cpp:299–405`) is not the call site. The explicit action instead calls `ModelVolume::repair` (`Model.cpp:3029–3047`) and `MeshRepair.cpp:1185–1214`. Its exact-vertex and repeated/duplicate-face cleanup is `clean_soup` and `remove_duplicate_triangles` (`367–439`), not `its_merge_vertices` (`TriangleMesh.cpp:690`), which is a separate indexed-mesh helper. The no-change fast path and the reconstructed face order come from `MeshRepair.cpp:339–365,1028–1073,1077–1105,1148–1180`.

## Included

`ares slice --export-stl` and `ares slice --export-stls <directory>` each write one binary file per object, in Native object order, from one STL or one plain geometry-only millimetre 3MF. The former accepts `--outputdir` and the latter gives its explicit directory precedence. One ordinary mesh volume and one printable instance per object; several separate build objects in a 3MF are supported. No arrangement or orientation; `--arrange 0` and `--orient 0` can explicitly disable them. For the admitted plain inputs use the Native standalone-input placement (`OrcaSlicer.cpp:1970–1979,6274–6281` and `Model.cpp:1896–1919`), including the imported 3MF's XY placement. STL accepts exact two-use edge connectivity (including the existing ADMesh winding pass); the ordinary 3MF path preserves input face winding and order, with no explicit repair requested.

With either STL export, `--repair` applies the exact-coordinate welding and removal of repeated-index facets and same-winding duplicates for an outward convex, connected single shell after cleanup. Unchanged meshes keep their face records; modified meshes use the reconstructed order, including face corner order. `--repair=false` skips explicit repair. The byte API in `ares-core` returns ordered `(object name, STL bytes)` artifacts, without reading/writing files, checking directories, or sourcing settings. Reuse existing project archive/XML parsing and the STL-import ADMesh subset; CLI alone resolves paths, reads/writes files and handles result reporting. Native witnesses can pass flattened presets as required by its startup; these are not embedded in the source or consulted by the byte writer.

## Deferred and rejected

Do not approximate arrangement, orientation, split/cut/scale/clone, slicing, G-code/3MF export combinations, repair without an STL action, multiple input files, multi-instance/repeated build references, components, non-millimetre units, affine transforms beyond translation, modifier or painted faces, project archives/metadata or auxiliary parts. Reject unsafe/non-leaf filenames. STL inputs needing ADMesh nearby-edge welding or facet deletion are outside this import subset. Explicit repair rejects shells needing tolerance-based welding, hole closing, inconsistent/inward winding correction, opposed duplicates, non-manifold or disconnected shells, nonconvex/self-intersecting surfaces, or shell nesting. No transfer of painting or repair logging is in scope. Deferred requests fail explicitly rather than exporting unchanged or partially repaired bytes. Argument conflicts use `CLI_INVALID_PARAMS` (`-2`); malformed model data uses `CLI_DATA_FILE_ERROR` (`-4`); export/write errors use `CLI_EXPORT_STL_ERROR` (`-11`, `Failed exporting STL files.`); missing input stays `CLI_FILE_NOTFOUND` (`-3`). See `Utils.hpp:44–56` and `OrcaSlicer.cpp:196–207`. Unlike the upstream writer's unchecked return in `Format/STL.cpp:45–50`, Ares does not report success on write failure.

## Verification

Live official and seeded Native runs use only synthetic geometry: standalone STL, multi-object plain 3MF, and an indexed 3MF with redundant vertices and facets which demonstrably loses a facet through explicit repair. Compare the ordered set of file names and every file byte, and check that the repair witness differs from its unrepaired geometry. Exercise rejected combinations and file errors separately. No recorded Native outputs or masks are part of the tests.
