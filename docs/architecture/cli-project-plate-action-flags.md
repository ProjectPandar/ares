# CLI action flags for saved project plates

## Upstream boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`) reads these options in `CLI::run` for the project, not separately for each plate. The `libslic3r` contracts are `DynamicPrintConfig` for the imported project settings, `Model::plates_custom_gcodes` for the layer events, and the model instance bounds used to compare the project with candidate `DynamicPrintConfig` machine presets. `CLI::run` applies these policies before its slice loop (`src/OrcaSlicer.cpp:6445–6457`).

| Option | Native behavior |
| --- | --- |
| `--normative-check` | A `coBool` defaulting to true (`src/libslic3r/PrintConfig.cpp:12842–12845`; `src/OrcaSlicer.cpp:1577–1579`). After importing the BBL 3MF, Native rejects a nonempty embedded `ConfigOptionStrings` `post_process` before merging supplied presets (`OrcaSlicer.cpp:1800–1810`); an explicit false bypasses that check, not other print or config validation. |
| `--skip-modified-gcodes` with `--load-custom-gcodes` | The skip flag is a `coBool` defaulting to false and the load option is a path (`PrintConfig.cpp:13185–13189,13218–13221`). Native loads `CustomGCode::Info` (`src/libslic3r/CustomGCode.cpp:33`), keyed at zero for `--slice 0` or at the selected plate number minus one (`OrcaSlicer.cpp:2048–2081`; `src/libslic3r/Model.hpp:1743–1749`). Native replaces the **whole** saved map, not just that entry, then erases only `CustomGCode::Custom` items from the resulting map (`OrcaSlicer.cpp:4104–4134`). That order is independent of argument order; other event types are retained. Without an external file, the filter applies to all saved plate lists. |
| `--downward-check` with `--downward-settings` | The check defaults to false; settings are an ordered, semicolon-separated candidate list (`PrintConfig.cpp:13108–13118`; `OrcaSlicer.cpp:1366–1402`). When enabled, Native loads machine presets (`OrcaSlicer.cpp:4723–4819`). Only when at least one target has loaded does Native compare it against the object bounds of every loaded plate (`OrcaSlicer.cpp:4540–4543,4698–4715,4823–4887`; `src/slic3r/GUI/PartPlate.cpp:4741–4759`). These are bounds of the imported model, not of the entire archive: `--slice N` passes `N` into the BBS importer, which skips objects absent from that plate but keeps all instances of retained objects (`OrcaSlicer.cpp:1758`; `src/libslic3r/Format/bbs_3mf.cpp:2202–2219`). It rejects a target on the first plate that exceeds the applicable dimensions, then reports surviving names in input order, omitting the field if none survive (`OrcaSlicer.cpp:4882–4893,548–549`). This is a project-level report, independent of upward compatibility and of how many G-code files are published. |

## Diagnosis and Rust destination

- `ares-cli/src/args.rs::DirectSliceArgs` does not parse these four flags. The Native-form 3MF route reaches `direct_project::run` via `direct_stl::run`; it rejects selection zero and its positive-plate context never sets either boolean. Keep the positive route's existing diagnostics, strict checks and statistics behavior. Route a Native-form all-plate 3MF request through the existing `slice_plates` adapter and batch core entry rather than invoking the positive route repeatedly. Both CLI forms should use the same option parsing and defaults; accept Native's bare and attached boolean values for the flags in this slice (`src/libslic3r/Config.cpp:1755–1783,1900–1906`).
- `main.rs::run_slice` already sets the booleans in `SlicerContext` for the `slice` subcommand. The loss happens in `ares-core/src/project_slice/cli_plates.rs::slice_cli_project_plates`: it forms `ProjectSource` with default flag values and uses the context only after building the applied plates. The single-plate counterpart `archive_plate::slice_source_with_archive` copies these controls into the source at preparation time. Do the equivalent before the batch project is loaded, for embedded, catalog and explicit preset sources. Use the context-aware `validate_load_settings_input` when checking inputs before reading replacement presets so that a defaulted preflight cannot reject `--normative-check=false`.
- Keep replacement and filtering at the loaded-project seam (`project_slice::{state,profile_entry}` and `project/plate_custom_gcodes.rs`). `ares-cli/src/custom_gcodes.rs` already reads the external file into `SlicerContext`; the batch adapter must supply the same zero-based selection. Apply the replacement once to the project, not separately to each view, and do not edit emitted G-code. Allow the combined flags in the `slice` subcommand's selected-plate form as well as in the Native form.
- `ares-cli/src/downward.rs` and `ares-core/src/downward.rs` already load and compare explicit candidates for the save-to-file single-plate route. Reuse their explicit candidate parsing and comparison for both selected and all-plate 3MF routes. Measure the imported objects by plate before narrowing to the applied slice views or publishing any G-code; for positive selections exclude objects the importer would omit, not all instances on other plates. Do not use completed `SlicedPlate` reports as the source of bounds. Only measure when candidates are loaded. Keep filesystem reads in the CLI and compatibility logic in core. Carry the one ordered result to the existing Linux result writer independently of the upward report, including exits that occur after the downward result was computed. Never synthesize an empty list field.

The CLI adapters and `ProjectSource` are compatibility shells around the upstream config, model and print preparation stages. This slice extends those stages' existing inputs and reports; it does not add a second slicing pipeline or a second archive import.

## Scope and exclusions

Include Native-form `--slice 0` and `--slice <n>` on saved 3MF projects, and correct the same propagation in the `slice` subcommand's selected-plate path. Preserve single-save behavior. Downward compatibility covers explicit machine files and the dimensional rules already used for the single-save route.

Deferred:

- Native's built-in `cli_config.json` lookup without explicit settings (`OrcaSlicer.cpp:1104–1173,4729–4734`), additional target features not covered by the existing checker, and downward checks on inputs without saved plate data. A no-candidate test must use a project whose machine has no built-in matches; omission with a matched built-in machine is not claimed as parity.
- Expanding `--skip-modified-gcodes` to machine/process or retained-filament G-code overrides during preset refresh (`OrcaSlicer.cpp:3098–3158,3243,3393,3670–3681`).
- Post-processing script execution, changes to script rendering, preset refresh, and non-CLI behavior. Do not copy undefined behavior or stale return-code uses from Native's error paths.

## Failure modes and verification

Use public CLI tests with synthetic saved projects, event files and explicit machine presets. For new Native-form cases use one argument vector for both binaries, with no Ares-only `slice` prefix. Run paired cases under both the official and seeded reference environments. Check exit status, output inventory and the relevant result or G-code with the existing comparison rules; a skipped reference does not establish parity.

1. **Parser accepts the flag but preparation ignores it.** An embedded `post_process` vector rejects by default, before preset loading, with no plate output; `--normative-check=0` permits slicing that same project. Check both selected and all-plate output naming. Use an inert declaration, not a runnable script. Cover the explicit preset preflight with the flag disabled.
2. **Filter is lost, acts on the wrong plate or runs before replacement.** Give both plates distinct saved markers and an external file containing a Custom and a PausePrint event. With no file, skip removes saved Custom events from both plates but preserves other events. With a file, skip removes its Custom event and keeps its pause; no saved marker survives the whole-map replacement, including on unselected map entries when slicing all plates. The file targets plate 1 for selection zero and the named plate for a positive selection. Run a load-only control and check the combined flags in either argument order.
3. **Downward compares only selected plates, unions results, or emits an empty field.** Use two different plate sizes and an ordered explicit target list with a machine that fits the first plate but not the second, between two machines that fit both. `--slice 0` must report just the two fitting names in order. `--slice 1` instead retains the narrower target if the distinct object on plate 2 is omitted by the importer. Verify the field is absent with no survivors, and that settings without the enabling flag are not loaded.
4. **Ordinary failure or publication behavior changes.** Check missing and malformed external input against the existing file/config failure channels; compare a missing downward target before any G-code is published. Preserve all-plate preflight, report placement and existing upward result behavior. Run the affected single-plate, batch and direct 3MF cases in addition to the new cases.
