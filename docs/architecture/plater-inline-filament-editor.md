# Object-list filament cell editor

## Source boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`). The cell writes the `extruder` model setting on a `ModelObject` or `ModelVolume` (`src/libslic3r/Model.hpp`; `src/slic3r/GUI/GUI_ObjectList.cpp:1151–1195`). `ModelVolume::extruder_id` (`Model.cpp:2690–2700`) resolves a volume's nonzero override or its object's slot for the model colour; the region configuration in `PrintObject.cpp:4289,4395` already consumes the same setting when slicing. The cell does not edit nozzle mapping, paint, or G-code.

## Prepare contract

- Use the existing filament badge as the inline control on object, normal part, and parameter modifier rows. The `Fila.` column in `GUI_ObjectList.cpp:459–482,6839–6851` opens a single row's `BitmapChoiceRenderer`; `ObjectDataViewModel.cpp:2010–2018,2271–2283` leaves non-filament rows without an editable value. Do not expose controls on instance, plate, negative volume, blocker, or enforcer rows. The cell selects a slot for its row, not for the current multi-selection.
- Follow the numbered, coloured options and active selection in `ExtraRenderers.cpp:313–362`. Use the current project slot palette. The **Default** option is present for a parameter modifier, not for an object or normal part (`GUI_ObjectList.cpp:475–480`). The modifier's Default is its unset/zero slot, not a positive slot styled with the parent's colour. No separate desktop-platform editor is needed: `GUI_ObjectList.cpp:1719–1755` and `:6691–6702` lead to the same model write. A click or keyboard activation opens the cell; choosing commits and closes it, and Escape closes without changing the model.
- When one filament slot is available, hide the filament column rather than leaving a disabled control. `Plater::on_filament_count_change` (`Plater.cpp:21440–21454`) calls `update_objects_list_filament_column` (`GUI_ObjectList.cpp:1052–1074`); `update_filament_colors` (`:1094–1099`) refreshes the displayed values after a palette change. A colour-only refresh does not write assignments. Slot count edits themselves are not part of this change.
- The cell writes the chosen positive slot to an object or eligible volume; a modifier's Default writes explicit `0`. An object edit removes `extruder` from **all** its volumes, including a modifier's positive or explicit-zero override (`GUI_ObjectList.cpp:1180–1193`). This is not the context menu action, which clears only normal parts (`:6964–6972`). Record the edit as one undo step; re-read the slots and update the list and viewport (`ObjectDataViewModel.cpp:1645–1653`; `GUI_ObjectList.cpp:6691–6702`; `3DScene.cpp:1791–1837`). Changing one part or modifier does not assign its siblings.

## Destination boundary

- `ares-core/src/plater/filament.rs` and `project/domain/filament.rs` own the single-row mutation and all-volume reset. Keep the cell and context-menu semantics explicit. Reuse the existing stable object/volume identities, typed region overrides, snapshots and `PlaterEdits` replay, including the distinction between an absent override and `Some(0)`. The slicing pipeline and model interpretation are unchanged.
- Extend `ares-wasm/src/plater/filament.rs` and the typed plater client with the corresponding single-row operation. The ObjectList filament cell uses that operation, the existing project palette, and returned model layout. The browser owns only editor lifecycle and presentation; passive badges for these rows become the entry point, not a second source of assignments. The context-menu action remains independent.
- Layer-range overrides (also accepted by the upstream desktop renderer), platform-specific wx editor workarounds, adding/removing slots or remapping persisted assignments, file serialization, and other filament management are outside this change.

## Public verification

- Before the implementation, exercise opening the inline cell and choosing a different slot in a synthetic two-slot project. Check numbered swatches, the current slot, and absence of Default for a normal part; exercise modifier Default and confirm cancellation does not change the row or scene.
- Start from a project with a normal part override and a modifier override. Compare an inline object edit with the existing context action: the former clears both overrides; the latter leaves the modifier untouched. Assert the resulting raw values via the public plater session as well as effective colours in Prepare. Undo and redo the single change, including the distinction between absent and explicit-zero modifier values.
- Exercise slicing on an independently authored equivalent project with two identifiable objects and distinct slot colours. Check the chosen tool by object and compare downloaded bytes to the equivalent baked Browser slice; compare the assigned project with Native in the corresponding canonical official and seeded lanes. Preserve the production comparators as-is. Run paired affected project and filament cases plus the affected Browser projects, formatting, all-target lint, and the WASM checks.
