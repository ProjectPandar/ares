# Belt multi-volume admission

## Upstream boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`), under `src/libslic3r`:

- `PrintObject::update_slicing_parameters` (`PrintObject.cpp:4463–4488`) merges the centered, transformed mesh boxes of all `ModelPart` volumes. `BeltTransformPipeline::compute_belt_height_and_floor` (`BeltTransform.cpp:121–168`) sweeps the resulting box's eight corners to estimate the object's tilted layer span and floor.
- `BeltSliceStrategy::apply_preslice_transforms` (`BeltSliceStrategy.cpp:12–79`) computes the actual lift from all `ModelPart` vertices using the volume matrix, the rotated object transform, and the belt floor. The lift belongs to the object, not to a volume. `slice_volumes_inner` (`PrintObjectSlice.cpp:171–206,227–262`) shares that object transform among model parts, negative volumes, and parameter modifiers; `slice_volume` (`:109–125`) composes each volume matrix after it.
- `update_volume_bboxes` and `trafo_for_bbox` (`PrintApply.cpp:622–630,972–1030`) keep region bounds in the pre-belt frame. `generate_print_object_regions` (`:1156–1198`) assigns model-part regions, records negatives without a region or parent, and creates modifier regions against intersecting parents. `slices_to_regions` (`PrintObjectSlice.cpp:323–398`) uses `!(belt_printer && BeltTransformPipeline::has_rotation(config))` to decide whether bbox Z is in the layer frame. `has_rotation` is true for any non-`None` axis, including Z, with `abs(angle) > EPSILON` (`BeltTransform.hpp:56–60`). If bbox Z is not in the layer frame, any range with more than one model part uses complex composition for all its layers. That composition still uses pre-belt XY overlap for clipping; it partitions modifiers, subtracts negatives, and merges same-region slices (`PrintObjectSlice.cpp:480–545`).
- Support annotations are not solid region inputs (`PrintApply.cpp:616–620`). `PrintObject::trafo_sliced` and `slice_support_volumes` (`PrintObjectSlice.cpp:1738–1796`) apply the shared belt transform in a separate support path. `Print::apply` derives support tilt from belt rotation (`PrintApply.cpp:1377–1392`); belt validation bans raft, not support in general (`Print.cpp:2144–2150`).

## Rust destination and scope

`crates/ares-core/src/project_slice/belt.rs::admit` admits multiple `ModelPart` or `ParameterModifier` volumes with at least one printable model part. This composition is limited to one object, one printable instance, by-layer order, one logical filament and one used slot, without support. Modifiers may change region settings such as `wall_loops` or `sparse_infill_density`, but may not select another filament. This does not change existing single-part admission for placements, multiple filaments or normal support. Defer `NegativeVolume`: the cutter probe matches Native region polygons but produces different walls downstream. Keep support blocker/enforcer volumes rejected even when inert. Do not change how layer-range settings are resolved.

`BeltSlice::new` reduces the centered box and exact rotated lift over printable model parts only, leaving negative and modifier volumes out of object height and floor calculation. Reuse `centering::center`, which already centers all printable model parts, and the existing `planning::plan_project` call from both height validation and slicing. `raw_intersections::slice_projected_objects` already composes `BeltSlice.centered_transform` with each volume transform: keep those per-volume intersections and their ordering, rather than merging meshes or building a separate belt region pipeline.

Keep `project::region_graph::object_region_graph` and `project_slice::volume_bounds` in the pre-belt frame. In `project_slice::region_slices::prepare_region_slices`, mirror the upstream bbox-Z predicate and complex-path condition. This does not widen the existing X/Y-only belt admission: Z is a rotation for the predicate but is still outside the admitted axes. Continue to use the slice plane to select the configured layer range and the existing XY overlap predicate for clipping. Reuse `region_slices::complex` for overlap ownership, subtraction, modifier partitioning and same-region merges; leave its flat-bed caller behavior unchanged. The flat-bed `support_material` path is outside this change.

The existing `gcode_emit::layers::object_entry` already represents a missing previous-layer boundary with an empty distance tree. A belt path can fail the first-layer speed test on physical layer zero, either by height above the belt or because the placement offset moves its bottom Z away from zero when no floor plane is available (`GCode.cpp:9316–9342,9693–9697,11615–11631`, `GCode.hpp:991–1003`, `PrintObjectSlice.cpp:995–1041`). The Native estimator uses an empty tree in that case, giving infinite distance rather than skipping overhang estimation (`GCode/ExtrusionProcessor.hpp:515–533,623–640`, `AABBTreeLines.hpp:337–344`). Volume composition reuses that estimator and the existing role-based wipe logic, which uses the resulting feedrate.

The spanning-modifier case also relies on aligned seam visibility using the sliced belt frame (`GCode/SeamPlacer.cpp:992–1030`, `PrintObjectSlice.cpp:1738–1743`). Keep that prerequisite in the seam pipeline; volume admission does not implement seam placement.

## Public behavior to verify

Use synthetic single-object 3MF inputs with explicit volume transforms. The pinned Official and Seeded binaries both slice a 90° X-rotation prism with an overlapping translated model part, a partially overlapping wall/infill modifier, or a negative cutter through the tilted layer stack. Each changes emitted motion relative to the single-part input. Blocker and enforcer variants also slice, with support enabled or disabled, but this prism produces no support extrusion; that does not establish support behavior on an overhang.

- Compare CLI slicing with both references using the existing ordered G-code comparator. Cover two overlapping same-region parts and offset the second part along machine Y under X-axis rotation so it owns the final printed extent.
- Cover a modifier that changes wall layout in only part of the model. Also cover a single modifier spanning both printable parts in the same layer range, exercising modifier partition and multi-part composition together.
- Keep the existing single-part, belt-disabled, and support rejection tests unchanged.
