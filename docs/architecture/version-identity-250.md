## Rust destination and decisions

The included behavior is exactly the final release identity: `2.5.0`, with Ares's existing brand and deterministic timestamp policy unchanged. `crates/ares-core/src/generation.rs::ORCA_SLICER_COMPATIBILITY_VERSION`, `gcode_header.rs::format_header`, and `project_slice/gcode_emit/header.rs::append_header` are the destinations. The first header is a temporary compatibility shell for the cited export boundary; this slice changes only its identity, not its pipeline diagnostics. Existing callers of the compatibility constant acquire the same identity without independent version policy.

Comparators still accept exactly one complete, anchored generator line of exactly one release. Native requires `OrcaSlicer 2.5.0` and its existing timestamp shape. The [fixed generated-at header contract](gcode-generated-at-header.md) supersedes this slice's undated-Ares requirement: Ares requires exactly `; generated by Ares 2.5.0 on 1980-01-01 at 00:00:00`, not a variable timestamp. No optional beta suffix, arbitrary version regex, alternate producer, fallback, or additional byte normalization is allowed. Existing vendor-branded timestamp treatment stays unchanged; vendor brand/version bytes remain protected.

## Test-first plan and failure modes

The agreed observation seams are the existing public byte/CLI output and exact generator comparator boundary, not new internal APIs. Comparator isolation contracts are necessary because a release-identity check must prove rejection independently of unrelated slicing mismatches. Failure modes: retained beta output on either public header path; accepting beta/rc/other releases; multiple, missing, wrong-brand, unanchored or malformed generator lines; masking vendor versions or non-generator bytes; conflating the internal `SLIC3R_VERSION` with the release label.

Commit order:

1. This source-cited specification and fixed inventory.
2. Tests first: update version-sensitive expectations and synthetic comparator inputs to exact `2.5.0`, add beta/rc rejection mutations, then demonstrate failures against the unchanged implementation under the 2.5.0 environment.
3. Feature: update the three runtime literals and listed comparison/substitution helpers, without broadening accepted identity. Preserve comments and provenance. Run focused contracts, public CLI checks and original OrcaSlicer E2E comparisons; retain commands, statuses and artifacts. Run `cargo fmt`, `cargo clippy` and tier-1-neutral WASM compilation.

The change must show exact-version acceptance and wrong-version rejection, deterministic public output, the unmodified upstream input identity, and no residual behavioral beta identity in the inventory. Unrelated Native parity failures remain failures, not weakened assertions.
