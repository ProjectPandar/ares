# ARD-0095: Reproducible generation inputs

The user requires identical Ares inputs to produce identical complete bytes.
Core `GenerationMetadata` and `SlicerContext` remain explicit execution inputs;
CLI and browser adapters use Unix epoch zero and seed zero instead of reading
the wall clock. This intentionally changes the adapters' default time policy,
not the slicing algorithms. The later user-requested header policy below
deliberately removes automatic generation-time formatting.

Upstream boundaries are `GCode.cpp` header emission and file-start template
timestamp setup (`2549–2581`), and `PlaceholderParser::update_timestamp`
(`PlaceholderParser.cpp:78–101`). Rust destinations are `generation.rs`,
`ares-cli/src/main.rs` and `ares-wasm/src/lib.rs`. The existing timestamp and
seed plumbing is retained, not replaced by a new slicing pipeline.

Ares-written ZIP members explicitly use DOS epoch `1980-01-01 00:00:00`,
because DOS timestamps cannot represent Unix epoch zero. Preserve compression,
member order and contents; retain deliberately varied timestamp fixtures that
test input-container invariance. Official Orca archives remain unmodified.
Currently ZIP writers exist only in test fixtures, not production adapters.

Included: deterministic adapter time and explicit ZIP defaults. Deferred:
unproven cross-platform/worker-count equivalence and any newly observed
ordering instability. Fixed timestamps alone do not establish those claims,
nor excuse real Ares parity differences or relax complete-output comparisons.

## Automatic header without generation time

After the filament-change timing checkpoint ff8a2517, remove only the automatic
generator line's date/time. Upstream `GCode.cpp:2576` writes `generated by %s
on %s` using `Utils::local_timestamp`; `GCode.cpp:2557,2705` instead initialize
template variables via `PlaceholderParser::update_timestamp`. That function
(`PlaceholderParser.cpp:78–101`, assignments at93,95–100) defines `timestamp`,
`year`, `month`, `day`, `hour`, `minute`, `second`; it emits no G-code itself.

Rust deletions (line numbers at ff8a2517): `gcode_emit/header.rs:2` metadata import, `:19` metadata argument,
`:24` timestamp destructure, and `:55–60` dated formatting. Replace the latter
with the exact static line `; generated by Ares 2.4.2`; remove only that
argument at `gcode_emit.rs:82`. Preserve all other header bytes and BTT behavior.

Retain all seven template variables and explicit core metadata. Removing them
would break the upstream template language and existing vendor/user templates
(e.g. Creality K2 machine-start generated-by comments). They remain deterministic
inputs, defaulting to epoch0; seed0 is unchanged. Do not rewrite supplied
templates or suppress their output. The user explicitly confirmed automatic
header only; vendor/custom template semantics are retained.

This is an explicit user-required output-policy deviation from upstream.
Strict comparison accepts only the dated Orca header and only the new undated
Ares header, then maps them to the same undated sentinel. Reject legacy dated
Ares headers; retain existing vendor normalization scope and every other byte
assertion. Only the derived normalized fixture hash changes, never raw fixtures.
