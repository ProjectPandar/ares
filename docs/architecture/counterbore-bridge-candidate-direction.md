# Counterbore bridge candidate direction and parallel tolerance

## Upstream source boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`):

- `src/libslic3r/BridgeDetector.cpp:190–225`, `BridgeDetector::bridge_direction_candidates`:
  - Collects the 5° resolution grid (`0..=PI / resolution`, `resolution = PI / 36.0`), every bridge contour/hole segment heading via `Line::direction()` (`:201`), and every open supporting edge heading via `Line::direction()` (`:208`).
  - Sorts candidate angles ascending and deduplicates adjacent pairs and the `(front, back)` wrap pair with `Slic3r::Geometry::directions_parallel(a, b, PI / 180.0)` (`:211–222`).
- `src/libslic3r/Line.hpp:179`, `Line::atan2_()`, and `src/libslic3r/Line.cpp:65–71`, `Line::direction()`:
  - Evaluates `double atan2 = this->atan2_();` and returns `0` when `fabs(atan2 - PI) < EPSILON`, `atan2 + PI` when `atan2 < 0`, and `atan2` otherwise.
- `src/libslic3r/Geometry.cpp:40–45`, `Slic3r::Geometry::directions_parallel`:
  - Adds `EPSILON` (`1e-4`, `src/libslic3r/libslic3r.h:57`) to `max_diff` before testing `diff < max_diff || fabs(diff - PI) < max_diff`.

## Rust destination

- `crates/ares-core/src/project_slice/perimeters/classic/counterbore/detector.rs` (`direction` and `parallel` helpers called by `candidates`).

The existing `direction` and `parallel` helpers in `detector.rs` are temporary approximations that differ from upstream:

1. `parallel` omits `+ EPSILON` (`1e-4`), using `PI / 180.0` (~1.0000°) instead of `PI / 180.0 + 1e-4` (~1.00573°).
2. `direction` derives the half-turn heading from `line.orientation()` (`atan2 + 2.0 * PI`, then `- PI` when `>= PI`) instead of `Line::direction()`, omitting the `|atan2 - PI| < EPSILON` snap to `0.0` and introducing an extra `2 * PI` round-trip on negative `atan2` values.

## Included and deferred behavior

### Included

- Replace `direction` in `counterbore/detector.rs` with the exact `Line::direction()` expression on `((line.b.y() - line.a.y()) as f64).atan2((line.b.x() - line.a.x()) as f64)` using `EPSILON = 1e-4`.
- Replace `parallel` in `counterbore/detector.rs` with `Slic3r::Geometry::directions_parallel` using `tolerance = PI / 180.0 + EPSILON`.

### Deferred

- Cross-target binary64 transcendental (`atan2`, `sin`, `cos`) parity between native libm and WebAssembly libm. No binary64 math kernel is introduced by this change.
- Adjacent `PerimeterGenerator.cpp:2289` partial counterbore mask opening radius (`ext_perimeter_width / 2`) in `counterbore.rs`, which belongs to a separate upstream owner.
- `BridgeDetector::unsupported_edges` and `Line::direction` callers outside `counterbore/detector.rs`.

## Failure modes

- A counterbore bridge slot edge whose heading lies in `(PI / 180.0, PI / 180.0 + 1e-4)` relative to a 5° grid angle (for example, `1.003°` relative to `0°`) fails to deduplicate in `candidates`, wins coverage over the grid angle, and emits a rotated counterbore bridge mask and altered walls/infill.
- A segment whose `atan2` lies in `(PI - 1e-4, PI)` is not snapped to `0.0` before sorting.
- A segment with negative `atan2` evaluates `(atan2 + 2.0 * PI) - PI` instead of `atan2 + PI`, risking a one-ULP rounding shift in candidate angle sorting and subsequent trigonometric rotation.
