# Native CLI headless 3MF project export

## Boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`) defines the action as a path-valued `export_3mf` in `src/libslic3r/PrintConfig.cpp:12734`. `src/OrcaSlicer.cpp:6423–6426` records the action and path, `7340–7371` enters export and prefixes the output directory, and `8081–8086` dispatches `CLI::export_project`. `8376–8405` forwards the model, effective print configuration and plate data to `store_bbs_3mf` with `Silence | WithGcode | SplitModel | UseLoadedId | ShareMesh`, optionally adding `SkipModel` for minimum saves. The port target is `store_bbs_3mf` (`src/libslic3r/Format/bbs_3mf.cpp:9723`), its `_BBS_3MF_Exporter::save_model` temporary-file boundary (`6346`), and the unsliced branch of `_save_model_to_file` (`6418` onward). Ares puts the archive writer behind a byte-in/byte-out `ares-core` API; CLI owns input/output path handling and disk writes. The existing project reader and CLI preset loading are input compatibility adapters, not alternate writers. The slice command without export is unchanged.

## Included

One headless unsliced single-nozzle FFF project with normal split-model output, one plate, one print instance of one ordinary mesh part. Inputs are STL or plain geometry-only 3MF with one ordinary mesh, with one flattened machine, process and filament preset supplied through `--load-settings` and `--load-filaments`. Ares exposes the path through `ares slice --export-3mf <path>`; this branch does not slice. Ordinary named settings and generated model/part/plate records belong to the project payload, not the ZIP container. The writer emits the ordered members produced by `_save_model_to_file`: content types, model parts and relationships, project settings, model settings, slice info (without a sliced plate), and package relationships, including any unconditional members Orca writes on this route. Configuration is the effective Orca config serialized with `ConfigBase::save_to_json` (`Config.cpp:1546–1557` and following), not an arbitrary copy of the input document. The proof uses a synthetic STL with Bambu Lab X1 Carbon and a synthetic 3MF with a non-BBL FFF machine; runs use both official and seeded Native executables.

## Deferred and rejected

No sliced output (`--slice`, loaded slice data, or packaged G-code, even if no new slicing was requested), thumbnails/bounding-box data from the renderer or source archive, minimum saves, arrangement/orientation/placement transforms requested on the export command, explicit plate selection, multiple models/plates/instances/parts, embedded project configuration, preset or auxiliary assets, paint, modifier and advanced model data. These are distinct upstream branches, not silently dropped members. Native may successfully perform a deferred operation (exit `0`, `Project exported to <path>` at info level, `OrcaSlicer.cpp:8407–8408`); this is not an assertion that Native rejects it. Ares reports an explicit unsupported export option/input. Its failure class is the matching Native CLI boundary: invalid export arguments use `CLI_INVALID_PARAMS` (`-2`, shell `254`, `Invalid parameters to the slicer.`); an archive it cannot export or output it cannot write uses `CLI_EXPORT_3MF_ERROR` (`-13`, shell `243`, `Failed exporting 3mf files.`) plus the destination in `Project export to <path> failed` (`OrcaSlicer.cpp:8410`). Missing source remains `CLI_FILE_NOTFOUND` (`-3`, shell `253`, `No such file: <path>`). See `Utils.hpp:44–56` and `OrcaSlicer.cpp:196–207`.

## Exact comparison

Enumerate the ZIP central directory in order and compare the full ordered vector of `(member name, uncompressed member bytes)` to live Native output. No ignored members, canonicalization, per-member masks, JSON/XML reserialization, version substitution, or sorted name sets. ZIP envelope fields (DOS timestamps, compression stream/level, flags, offsets and ZIP64 records) are not member payloads. Native miniz assigns wall-clock local time to memory and staged records with no explicit time (`deps_src/miniz/miniz.c:6190–6196,6813–6821`); Ares uses a fixed ZIP-representable epoch (1980-01-01) instead of reading the clock. The test also checks repeatability of complete Ares archive bytes. Dates *inside* the model are exactly the upstream empty `CreationDate` and `ModificationDate` values (`bbs_3mf.cpp:7256–7258`). The generated compatibility and Orca version strings come from `version.inc:10,17`, the 3MF marker from `bbs_3mf.cpp:169,173,7283`, and project/slice versions from `8203,8729`. UUIDs use the exporter’s integer identifiers and suffix constants (`328–333,7533–7554,7685,7864–7870`), not random UUIDs. If a Native run produces differences in any member bytes, identify the writer branch or input before shipping rather than alter the comparator.
