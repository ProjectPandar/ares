# Discovery: dynamic filament override keys escape `validate(FullPrintConfig)` range check

**Status:** discovery complete → corrected spec + RED plan. Found with a long-retraction skirt project.

## Reproducer

- `filament_retraction_distances_when_cut=["5"]` in `project_settings.config`.
- **Native CLI 2.4.2**: slices normally (verified on `ctl.3mf` patched with the key → `plate_1.gcode` produced, no error).
- **Ares**: `SliceError::InvalidInput` — `5 not in range [10,18]` (`options/overrides.rs:290-297`, metadata min=10/max=18 from `PrintConfig.cpp:5225-5226`).

## Upstream class model (corrected)

There is **no `FilamentConfig` class**. The hierarchy (`PrintConfig.hpp:7-12`, `:1480-1481`, `:1660-1665`):

```
FullPrintConfig ⊇ PrintObjectConfig + PrintRegionConfig + PrintConfig
PrintConfig derives (MachineEnvelopeConfig, GCodeConfig)
```

`GCodeConfig` statically declares `filament_diameter`, `filament_max_volumetric_speed`, temperatures, and also `retraction_distances_when_cut` (`PrintConfig.hpp:1379`, `ConfigOptionFloats` member). These **are** `FullPrintConfig` members and ARE range-checked.

The keys that escape are the **dynamic `filament_extruder_override_keys`** — the 19 nullable mirror options created with `add_nullable` at `PrintConfig.cpp:7288-7320` from the list at `PrintConfig.cpp:63-84`:

```
filament_retraction_length, filament_z_hop, filament_z_hop_types,
filament_retract_lift_above/below/enforce, filament_retraction_speed,
filament_deretraction_speed, filament_retract_restart_extra,
filament_retraction_minimum_travel, filament_wipe_distance,
filament_retract_when_changing_layer, filament_wipe,
filament_retract_before_wipe, filament_long_retractions_when_cut,
filament_retraction_distances_when_cut
```

They are `add_nullable` entries on the `DynamicPrintConfig` def, **not** static members of any `StaticPrintConfig` class, so `fpc.apply(*this, true)` in `DynamicPrintConfig::validate` (`PrintConfig.cpp:8876-8878`) drops them before `Slic3r::validate(fpc)` runs its `cfg.keys()` range loop (`:10515-10565`).

## Empirical verification (official Native 2.4.2)

- `filament_retraction_distances_when_cut=["5"]` → **accepted**, slices (`plate_1.gcode` produced).
- `filament_max_volumetric_speed=["-1"]` (GCodeConfig static member, `min=0` at `PrintConfig.cpp:2550-2558`) → **rejected**: `filament_max_volumetric_speed: -1 not in range [0.000000,34028234…440.000000]`, exit path `CLI_INVALID_VALUES_IN_3MF`.

## Spec

Ownership rule: **a key is range-checked iff it is a static member of `FullPrintConfig` (directly or via its derived-from chain `PrintObjectConfig`/`PrintRegionConfig`/`PrintConfig`→`MachineEnvelopeConfig`/`GCodeConfig`)**.

- Ares destination boundary: `crates/ares-core/src/options/overrides.rs` `validate_numeric_range`/`validate_entry`.
- Skip the min/max rejection **only for the 16-key `filament_extruder_override_keys` set** (`PrintConfig.cpp:63-84`; dynamic `add_nullable` creation `:7288-7320`). Ares counterpart: the typed `RetractOverrides` struct in `crates/ares-core/src/options/filament_options/retract_overrides.rs:20-35`, which enumerates exactly those 16 `filament_*` nullable fields — expose/reuse that set (e.g. a `const` list or the wire-field table already keyed by the same names) for the skip. Do NOT use `FILAMENT_OPTION_KEYS`/`FILAMENT_OPTIONS_WITH_VARIANT_KEYS` in `options/registry/key_lists.rs` — those are different upstream lists (`PrintConfig.cpp:7363-7372` unprefixed extruder sources; `:8376+` variant keys) that do not match the 16 dynamic keys.
- Keep the check for every other key, including `GCodeConfig` static `filament_*` members (`filament_diameter`, `filament_max_volumetric_speed`, `filament_retraction_length`'s static counterpart is NOT static — it's only dynamic; `retraction_distances_when_cut` static member DOES exist in `GCodeConfig` (`PrintConfig.hpp:1379`) and remains checked when set as the bare `retraction_distances_when_cut` key).
- `nil`/type-shape validation stays.
- Deferred: GUI clamps, SLA path.

## RED plan

Modes: official + seeded0.

- **Target** (`filament_retraction_distances_when_cut=["5","5"]` on the long-retraction base): Native accepts & slices; Ares fails `5 not in range [10,18]` pre-fix → FAIL pre-fix / PASS post-fix, byte-equal output post-fix modulo `; generated by`.
- **Control-1** (`filament_retraction_distances_when_cut=["15","15"]`): in-range → PASS both pre- and post-fix.
- **Control-2** (`filament_max_volumetric_speed=["-1","-1"]`): GCodeConfig static member with `min=0` → **Native rejects** (`not in range`), so Ares must also reject both pre- and post-fix. Guards against over-scoping the skip to all `filament_*` keys.
