# ARD: Run option-only STL through the OrcaSlicer print lifecycle

## Status

Planned. Ares base `8b28296357e58d5f418c4540aa92c27d8b10c4df`. Upstream source pin `40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`; all OrcaSlicer line references are at this pin. This is a [rewrite-gated milestone](ard-0020-future-milestone-rewrite-gate.md), not a second slicing pipeline.

## Why this is a migration

An option-only STL is a single raw STL sliced with explicit `SliceOptions` and no selected presets, not a 3MF or a profile-backed STL. OrcaSlicer sends the model and effective config into the same `Print` lifecycle regardless of that input distinction. Ares instead sends option-only STL through a temporary scanline pipeline with its own placement, fill model, and debug G-code writer.

On the committed `tests/parity/cube10.stl` with `monotonicline` and the same explicit layer reset (`G92 E0`), Native emits two first-layer walls and a 9.550 mm outer-wall span; the standalone path emits one wall and a 10 mm span. Bringing the input to Z=0 does not close the wall, top-fill, or travel differences. This is not merely a missing Spiral Inset enum or a different header.

## Decision and source boundaries

Route option-only STL through the existing `ares-core::project_slice` implementation of `libslic3r::Print::apply`, `Print::validate`, `Print::process`, and G-code export. Keep STL/config ingestion distinct from 3MF and preset resolution; converge before apply/process. Replace the standalone production path and remove its public stage API. Do not keep a fallback, feature switch, second pattern generator, or reconstructed legacy stage stream.

`SliceOptions` remains the public input transport, not a second config engine. At ingestion, map its supported scalar/vector and percentage representations to the corresponding upstream `ConfigOption` values; verify conversion against witnessed inputs. Use existing typed value validation rather than letting an unrelated 3MF deserializer silently decide the contract. Keep upstream apply-time, model-dependent normalization in the shared lifecycle. No slicing behavior goes into an adapter.

## Public boundaries and scope

- **Rust:** retarget `ares_core::slice`, `slice_stl_validated`, and `validate_stl` to the same loaded model/config seam. Keep the asynchronous bytes/options-to-bytes interfaces and the existing selection of print validation. If object identity is needed by an adapter, pass basename/metadata to core as data and make the default for a byte-only caller deterministic. Compare identical object identities in parity tests rather than stripping labels from output.
- **CLI:** the existing raw `ares slice --options <json> <stl>` branch in `crates/ares-cli/src/main.rs` parses inputs, supplies the basename, maps errors, and writes bytes. It shares processing with the Rust and WASM entries. Do not add `--arrange`, `--scale`, `--rotate`, `--slice 0`, or a JSON equivalent to bypass that deferral. Those CLI options are a separate slice. Also defer adding Ares admission for literal bare CLI STL or process-only `--load-settings` and expanding CLI report contracts. Native `--slice 0` is used only to invoke the reference.
- **WASM and Web:** keep `crates/ares-wasm/src/lib.rs::{slice_stl,slice_stl_bytes}` byte output and error propagation; `web/packages/ares-wasm-js` continues returning `toolpaths: null` for `sliceStl`. Do not attach a viewer, record preview moves, or change the protocol. No dependencies move into `ares-vgcode` and no filesystem I/O enters `ares-core`.
- **Processing:** reuse the current project fill, wall, support, travel, and writer behavior, including whichever upstream patterns are already implemented there. A new fill algorithm or enum admission is not part of this milestone. Spiral Inset is an integration witness when its separately ported project implementation is present; the requested base predates that port. Do not import a second implementation or claim Spiral Inset parity on the base. Defer multipart/foreign 3MF admission, explicit transforms and orientation, general arrangement changes, and independent geometry/writer gaps. If a deferred gap blocks a strict acceptance witness, report it for a separate scope decision rather than weakening the comparison.

## Remove the temporary scaffold

This decision supersedes [ARD-0008](ard-0008-stage-diagnostics-before-perimeter-infill-ports.md) for the option-only runtime and its stage API. The existing standalone path serves no production caller after the switch. Remove it in the migration, not as an optional follow-up:

- Delete `pipeline.rs` and its diagnostics, `infills.rs` and its standalone fill dispatch, `print_paths` and standalone move/extrusion/speed assembly and G-code formatting that only served this path. Remove `SlicingPipeline`, including `layer_infills` and `layer_print_paths`, `PipelineDiagnostics`, `PipelineStage`, `run_slicing_pipeline`, `InfillPath`, `LayerInfills`, `LayerPrintPaths`, `PrintPath`, `generate_infills`, `generate_print_paths`, and the other scaffold-only public stage exports. No aliases, deprecated re-exports, or wrappers recreating them.
- Audit `lib.rs` and the dependents of mixed modules before deletion. Preserve live shared types and kernels used by the project port under their surviving owners; remove obsolete stage producers and exports instead of deleting a shared numeric or geometry implementation wholesale. In particular, remove the unwired `project_slice/raft/emit.rs::apply_raft_to_stream` bridge for `LayerPrintPaths`; retain the project raft emission used by the common path. Do not change live project behavior for cleanup.
- Replace CLI assertions on the standalone `;PRINT_PATH`, segment and stage-count comments with public behavior assertions before retiring the formatter. Discard tests of the removed representation with the removal; keep coverage of surviving motion/validation in Native-backed end-to-end tests. Verify tracked code and public exports have no remaining scaffold entry points. Leave no hidden diagnostic slicing route in WASM or Web.

## Review and implementation order

1. **Specification review.** Review this decision and linked roadmap exit criteria before any test or code commit.
2. **Public witnesses before the switch.** On the unchanged base, commit a failing Native/Rust/CLI comparison for a grounded `cube10.stl` with default `monotonicline` and only a valid layer reset, plus a case with an explicit override that changes an exported value. Derive above-bed and below-bed inputs from the same STL and record their placement failures before the fix. Native must successfully slice these positive cases. Capture the first whole-stream differences and use invalid input and missing-reset rejections as controls.
3. **Entry switch and removal.** Complete the configuration, place the instance, and use the shared single-STL entry. Prove default XY placement as part of whole-stream parity. Grounded, above-bed and below-bed inputs must produce the same ordered printable layers and match Native for each corresponding input. Remove the standalone route and public exports at the switch, with the test migration and consumer audit. Keep a stable inventory of surviving Native-backed controls in both lanes and separately enumerate retired scaffold assertions.
4. **Integration and exit.** Exercise the project-pattern reuse seam, including the Spiral Inset witness on the combined history once its project port is present. Retest existing profile-backed STL, ordinary 3MF, and WASM/API validation and byte contracts. Do not settle for top-only motion equality on a default request that still fails whole-file parity.

## Acceptance evidence

Run official and seeded Native twice each for new witnesses; use committed authored inputs or runtime-derived edits thereof, not committed Native output or exports. For successful witnesses compare the entire ordered Native, API, and CLI G-code using the existing strict comparator (generator identity only), and require exact API/CLI bytes under equivalent metadata. For rejection compare the applicable validation contract and absence of G-code, including the `G92 E0` diagnostic for the no-reset case. Artifact receipts record commits, commands, input hashes, and first differences. For unchanged controls compare identical scoped case IDs before/after in each lane, require no pass-to-fail transitions or required Native skips, and retain known failures explicitly. Check fmt, workspace all-targets Clippy with warnings denied, WASM core/adapter build, and diff cleanliness. Bytes and tests, not the presence of a new entry point, determine milestone completion.
