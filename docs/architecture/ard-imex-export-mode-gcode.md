# Resolve and render IMEX mode G-code at export startup

## Upstream boundary

Port the IMEX mode script path of OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`):

- `src/libslic3r/IMEXHelpers.cpp:648–678`, `imex_mode_at` and `find_imex_mode`, look up the first exact match in `imex_mode_names`. A missing entry in `imex_mode_active_tools` or `imex_mode_gcodes` contributes an empty string, not a wrapped vector index or a missing mode row.
- `src/libslic3r/GCode.cpp:4131–4219`, `GCode::_do_export`, reads the effective first print object's `imex_parallel_mode` for an IMEX printer. An empty setting means `primary`. An unresolved non-primary mode or a non-primary row with no active tools falls back to the Primary row. Primary can itself define G-code. The exporter sets the three read-only placeholders `imex_mode`, `imex_mode_index`, and `imex_mode_gcode` (the raw script) before any template is processed. For non-IMEX exports those values are empty, zero, and empty respectively.
- `GCode.cpp:4221–4231` invokes `placeholder_parser_process("imex_mode_gcode", …, initial_extruder_id)` before evaluating `file_start_gcode` and buffers the result. `:4381–4404` processes machine start independently, uses that template alone for the startup temperature checks, emits the custom tag and any chamber startup G-code, then writes the buffered mode G-code immediately before the machine start G-code. The distinction between render order and file order is required: mode script globals can be read by file start, even though file start is written first. The shared context is `GCode.cpp:3581–3588,5385–5389`.

## Diagnosis

All nine Xplorer Dual Gantry, IDEX and IQEX profiles (0.4, 0.6 and 0.8 mm) select `primary` and define `SET_PRINT_MODE MODE=PRIMARY` in the corresponding mode row. The line is not in `machine_start_gcode`. On each unmodified project the two executables succeed with identical CLI arguments. The sole executable-block difference is that Ares omits this line immediately after `;TYPE:Custom`. Erasing only the selected mode script in the representative project makes the executable blocks identical. A mode script that declares a global and prints a marker is processed before file-start and machine-start templates in Native; the current Ares exporter never evaluates it.

After this omission, all nine stock comparisons still differ in `physical_extruder_map` in the config footer. That is a separate output difference, not evidence for a second startup cause.

## Rust destination and scope

Resolve the startup mode from the effective print-object and typed printer settings, at `crates/ares-core/src/project_slice/gcode_emit/orchestration.rs` before `file_start::append`. Expose only the existing registered mode-table settings needed by this path; `options/printer_options/gcode_source.rs` already carries `is_imex`, the mode names and tools, but not the mode scripts as a typed emitter source. Use the resolved object's actual mode; do not choose by printer name, assume Primary is table index zero, or unconditionally interpret any printer with nonempty mode scripts as IMEX. The mode table used by arrangement is not the export entry point.

Supply the three resolved scalars through the shared export template context (`gcode_emit/template.rs`), during file start and later export template calls. Render the nonempty selected script once, using the existing export-owned placeholder dictionaries and template context, not a new independent parser or post-processing text replacement. The mode template uses the ordinary custom G-code result and named error handling. Make the buffered text available to `gcode_emit/machine.rs::append_start` after the custom tag and chamber startup and before the independently rendered machine-start template. Do not feed the mode output into the scanner for machine-start temperature commands or last-tool detection, and emit no new line for an empty result. The existing file/machine startup emission remains the destination for its corresponding upstream operations; do not add an unrelated export phase or modify the profiles.

This slice does not port parallel tool routing state (`m_imex_parallel_mode`, `m_imex_head_filament_map`), gantry geometry, multicolour eligibility, heater mapping, footer-map serialization or noncritical IMEX warning presentation. Mode selection includes the fallback that determines the emitted script, not the separate warning UI. Preserve the existing template RNG and writer-output contract; defer unrelated startup writer-state or error-channel changes. No changes to legacy placeholder grammar or suffix lookup.

## Verification

1. A synthetic printable project defines an arbitrary mode script, not the vendor command. Native and Ares compare header and executable markers: the selected mode script declares a global, file start reads it before that script appears in the stream, and machine start reads it after the script. Assert the reported mode name and index and the exact placement after the custom tag and before the machine-start text. Contrast an empty selected script and a non-IMEX control with a populated table. Use two distinguishable rows so selection is by name rather than inferred by position; test the lookup rules without asserting unported parallel tool routing.
2. Exercise invalid mode script syntax through the public CLI and compare the named template failure, exit and absence of final G-code. Add a small witness if a temperature command in the mode script would otherwise affect machine-start temperature detection.
3. Re-run all nine unmodified stock projects with identical Native/Ares arguments, in ordinary and seeded reference environments. Compare the entire executable blocks without suppressing lines. Retain the next-difference distribution separately; do not claim complete file parity while the footer-map difference persists. Add no stock-derived fixtures or Native outputs.
4. In both environments compare affected IMEX, file-start and machine-start, custom-G-code and placeholder cases with the same filter at base and tip. Require no case to move from pass to fail and all new cases to pass.
