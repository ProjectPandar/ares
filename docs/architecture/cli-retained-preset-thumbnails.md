# Preserve the retained printer's thumbnail option in CLI slices

## Upstream boundary

OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`) loads the embedded 3MF configuration through `ConfigBase::load_from_json` (`src/libslic3r/Config.cpp:1151–1153`). `PrintConfigDef::handle_legacy_composite` (`src/libslic3r/PrintConfig.cpp:10046–10073`) parses thumbnail dimensions and formats a nonempty list with comma-space. This is the JSON-load boundary, not a rule for every subsequent assignment of the option.

The later retained preset pass in `CLI::run` uses `refresh_unlisted` if `--uptodate` is active or any entry of `different_settings_to_system` is nonempty, even if only the process entry is dirty (`src/OrcaSlicer.cpp:2775–2779`). With a retained system printer, no replacement machine, and no loaded machine settings, `load_project_preset` builds a printer configuration and applies changed values back to the print config (`:3164–3200`). `PresetBundle::project_different_keys` adds reserved preset keys to the per-column list (`src/libslic3r/PresetBundle.cpp:5525–5531`); `Preset::load_external_config` resolves the system preset and applies values not listed as different (`src/libslic3r/Preset.cpp:1090–1115`, `PrintConfig.cpp:12139–12201`). For the printer the dirty column is `filament_count + 1`. If refresh is inactive, this pass supplies missing keys without overwriting present embedded values. If `thumbnails` itself is dirty, the loaded project value wins.

`thumbnails` is a scalar `ConfigOptionString` (`PrintConfig.cpp:8598–8603`). The X1 Carbon 0.4 system preset and its parents (`resources/profiles/BBL/machine/{Bambu Lab X1 Carbon 0.4 nozzle,fdm_bbl_3dp_001_common,fdm_machine_common}.json`) do not set it, so they carry the registered `48x48/PNG,300x300/PNG` default. `resolve_system_preset` obtains the resolved preset config (`PresetBundle.cpp:724–755`); the CLI copies the option, not the original archive token and not a recomposed thumbnail list (`OrcaSlicer.cpp:3187–3193`). `ConfigOptionString::serialize` (`src/libslic3r/Config.hpp:1157–1175`) escapes the string but does not format its separators. `GCode::append_full_config` emits that value (`src/libslic3r/GCode.cpp:8370–8379`). A retained preset carrying a different value must keep its own spelling; do not remove spaces from thumbnail strings globally.

## Rust destination and scope

For ordinary BBL-family saved FFF projects sliced through the CLI with a retained system printer, carry the winning `thumbnails` string from the post-load retained printer option copy through typed config application, without a second JSON-load thumbnail composite. The CLI destination is `crates/ares-cli/src/slice_plates.rs::run` and its `crates/ares-core/src/project_slice/source.rs::apply_direct_catalog` path, using `crates/ares-core/src/profiles/project_refresh/preset.rs::refresh` for retained-option ownership and precedence. For ordinary CLI slicing, resolve the installation's resource directory when none is supplied. Use the same catalog refresh for explicit and installed resources: refresh retained printer, process, and filament keys through the existing merge rules, including missing-key fill and protected dirty columns. A resource location does not change which keys can be refreshed. If no installed catalog is available, this path has no system preset values to copy.

In the catalog route the correct source can already win, but `Project::apply_project_preset_refresh` currently calls `options::json_deserialize::deserialize_refreshed_config`, which uses the JSON project builder and reapplies the thumbnail composite. Preserve the post-copy scalar at this CLI application boundary, not by editing the G-code emitter. Keep `project/load.rs::load_project_raw` and the web plater's GUI composition unchanged. No change to direct STL, explicit replacement files, non-BBL printer admission, thumbnail validation or image generation, general preset discovery, or other option merge rules. Do not route GUI-open config through the CLI refresh semantics.

## Public verification

Use a synthetic one-filament X1 Carbon project with two valid PNG sizes and `enable_prime_tower=0`. Slice the same archive in both CLIs on the same plate. Make one variant set the process dirty column to `enable_prime_tower` and a control leave all columns empty. Compare the exact generated `thumbnails` and `enable_prime_tower` config lines with the official and seeded Native runs: the dirty process variant takes the retained printer default, while the control keeps the comma-space loaded string. Both preserve the disabled tower. Also use alternate embedded dimensions with and without `thumbnails` in the printer dirty column to distinguish a retained option replacement from whitespace-only formatting. In the installed-resource case, also save `nozzle_height=5.2` without marking it dirty; the retained X1 Carbon printer's `4.2` must win alongside its thumbnail string. Keep the CLI comparison and GUI load behavior separate; do not normalize thumbnail separators in assertions.
