# Direct CLI `--no-check`: retained validation errors

Upstream: OrcaSlicer v2.5.0 (`40ecc66f7`). This slice ports the report behavior for an existing fatal `Print::validate` result. It does not mean “disable validation.” The witness is a synthetic 3MF with two by-layer spiral-vase copies. Both orders of `--no-check` and `--slice` must still fail with `CLI_VALIDATE_ERROR` (`-51`, POSIX exit 205). Only when `--no-check` precedes `--slice` does `result.json.error_string` carry the validator's diagnostic instead of the generic CLI message. Stderr contains the same diagnostic in both modes; neither mode emits G-code. A successful synthetic STL slice is a control for the full report and complete exported G-code.

## Upstream order and stage boundaries

- `OrcaSlicer.cpp:1389–1397`: check the parsed `strict` and `no_check` globally before loading input. The existing parameter-error path still owns their mutual exclusion, regardless of order (`cli-strict.md`).
- `OrcaSlicer.cpp:8202–8227,6283–6297,6426–6444`: action keys follow command-line order. `no_check` starts false and changes when its own action is reached. A later occurrence cannot retroactively affect a slice.
- `OrcaSlicer.cpp:6986–7040`: apply the print, set the flag, and **call** `Print::validate` (`libslic3r/Print.cpp:1972`). Native only downgrades a returned `STRING_EXCEPT_LAYER_HEIGHT_EXCEEDS_LIMIT`; at this pin the type is declared in `PrintBase.hpp:32`, with no producer in `Print::validate`. Do not infer that nozzle/layer-height validation is disabled. All other validator errors, including filament/bed, filament temperature and sequential/layered collision, remain fatal with the same code and stderr; the flag selects their detailed report string. Empty-print rejection after validate is separate.
- `libslic3r/PrintObject.cpp:962–992`: skip checking support necessity when support is disabled, so its `SlicingNeedSupportOn` warning is not generated. Support and raft generation are not bypassed. `Print.cpp:3946–3964` skips `ConflictChecker::find_inter_of_lines_in_diff_objs` during processing (after path preparation); `OrcaSlicer.cpp:7134–7140` consumes its result, not a `Print::validate` collision. `OrcaSlicer.cpp:7142–7174` retains the noncritical warning policy and only gates the fatal treatment of the critical `SlicingEmptyGcodeLayers` and `SlicingGcodeOverlap` notifications; this is not a suppression of every warning or its plate message.
- `GCodeProcessor.cpp:2940–3105` populates `gcode_check_result` independently of `no_check`. `OrcaSlicer.cpp:7193–7208` still checks it after G-code export and rejects an unprintable path. The separate `toolpath_outside` result member (reset in `GCodeProcessor.cpp:2694–2695`, persisted by `Format/bbs_3mf.cpp:1733,8785`) is not that CLI gate or a switch controlled by this action.

## Rust boundary

The direct CLI keeps the global `--strict` pair rejection and derives the slice-local flag from the argument indices. On the direct project route, the existing `ares-core::print::validate` produces `SliceError::Validate`. The CLI uses its diagnostic for the report when the slice-local flag is active. Do not change the validator, G-code writer, existing warning types, `slice` subcommand, or WASM API. Verify with identical argv for both binaries, isolated cwd and private Native temporary directories. Check exit, stdout/stderr, recursive output inventory including cwd, the complete report (normalize elapsed times only), and the complete G-code when present (normalize only the generator identity and generation timestamp).

Deferred: other validation error families, the unproduced layer-height downgrade, support-necessity and typed critical warning gating, the processing-time path conflict checker, all-plates and repeated-action traversal, and any separate G-code/3MF checking coverage. The direct option does not claim any of these suppressions. Do not reuse it to skip the independent post-export bounds gate.
