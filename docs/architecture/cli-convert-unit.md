# Infer STL units before direct slicing

Reference: OrcaSlicer 2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`).

- `src/libslic3r/Format/STL.cpp:18–40` loads a repaired STL as one object; `TriangleMesh.cpp:177–207` calculates and stores its volume. `Model.cpp:2625–2646` sums only model-part mesh volumes weighted by the absolute determinant of the volume and, if present, first instance transforms. This is solid volume, not a bound on any dimension or on bounding-box volume.
- `src/OrcaSlicer.cpp:4909,4961–4972` runs the transform before actions, choosing meters before inches once per model (`PrintConfig.cpp:12967–12970` defines the boolean). `Model.cpp:975–1000,1016–1028` uses strict `< 0.008` for meters and `< 8.0` for inches, testing whether any object qualifies. For inches, a cut candidate qualifies only if no other object with its cut ID meets or exceeds the threshold. A meter inference does not fall through to an inch pass for other objects.
- `Model.cpp:1003–1014,1030–1041,1990–1998,3116–3125` applies binary32 factors `1000` or `25.4` only to objects strictly below the chosen threshold, but then scales **all** their volumes (including non-model parts), volume offsets and hulls, invalidates their bounds and marks every scaled volume's origin as meters or inches (`Model.hpp:843–850`). `TriangleMesh.cpp:258–277` scales vertices in binary32. The standalone volume helpers at `Model.cpp:3151–3165` apply the same factors and provenance but zero the volume offset; the CLI calls the object path, which scales rather than zeroes the offset.
- Slicing uses the transformed model (`OrcaSlicer.cpp:6986,7099–7114,7193`), so the change precedes validation and layer generation: a model too small to slice without conversion can produce a full-sized print with conversion. STL export takes transformed object instance meshes (`OrcaSlicer.cpp:6398–6412,8348–8364,8440–8479`; `Format/STL.cpp:43–57`; `Model.cpp:1675–1703`); it writes binary geometry, not source flags. The BBS 3MF path (`OrcaSlicer.cpp:8061–8086,8376–8405`) stores scaled geometry as millimeters (`Format/bbs_3mf.cpp:7196,7664–7688`), with the applicable `source_in_meters` or `source_in_inches` key (`:438–439,8388–8392`, read at `:5452–5455,5634–5637`).

The Rust boundary is `ares_core`'s STL/project geometry API: infer a source unit from imported geometry, then offer conversion to millimeters while retaining provenance. The CLI owns `--convert-unit` and supplies converted geometry to the existing direct STL slice producer before placement. No change to default imports. Wiring STL export to this API is deferred: Native produces different binary geometry for the two converted cubes and identical bytes for the millimeter control, but the STL export action is maintained separately. Inference uses the solid volume already calculated by the STL repair path for closed meshes (`deps_src/admesh/util.cpp:248–297`), before recentering. Existing fallback imports without valid closed-mesh connectivity have no inferred unit. Saved 3MF input/export wiring, cut groups, assembled/heterogeneous models, standalone volume conversion and arbitrary action combinations are outside this STL slice.
