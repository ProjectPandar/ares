# Ares package version in the G-code producer line

## Source and destination

At OrcaSlicer `40ecc66f7`, `src/libslic3r/GCode.cpp:4239–4242`, `GCode::do_export` writes the header block and `; generated by %s on %s` using `header_slic3r_generated()` and a timestamp. `src/libslic3r/utils.cpp:1515–1518` supplies the application identity. The Rust destinations are `crates/ares-core/src/gcode_header.rs::format_header` and `crates/ares-core/src/project_slice/gcode_emit/header.rs::append_header`. The former remains a temporary compatibility shell around the upstream export concept, not an independent pipeline extension.

## Included behavior

Keep the upstream producer-line shape, Ares branding, fixed `1980-01-01 at 00:00:00` timestamp, and BTT header omission. Use the Ares version from root `Cargo.toml` `[workspace.package]`, initially `0.1.0`, inherited by all four workspace crates. Both emitters obtain it through `env!("CARGO_PKG_VERSION")`. Header expectations and strict producer-line comparators derive the Ares version from package metadata while retaining OrcaSlicer's own version checks.

The configuration block, saved project-settings `version`, and 3MF `Application` remain on `ORCA_SLICER_COMPATIBILITY_VERSION` (`2.5.0`), because those values select OrcaSlicer's legacy conversions. The producer version is not a configuration compatibility version.

## Deferred behavior

Do not change browser about text, npm versions, timestamp policy, configuration conversions, other header fields, or adjacent export behavior.

## Failure modes and behavioral verification

A producer could retain the compatibility version, one public output path could use a different version, or strict comparison could reject the new identity. Exercise byte-input slicing and project slicing through public APIs, assert exactly one package-version producer with the fixed date, and retain BTT omission checks. Run all tests that inspect producer lines against both Native installations, including strict whole-file comparison. Check Moonraker's `PrusaSlicer.identify` recognizes Ares and its package version. Existing configuration and 3MF round trips must retain `2.5.0`. Formatting, workspace linting, and browser-WASM compilation must succeed.
