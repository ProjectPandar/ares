# Single 3MF import for CLI preset slicing

## Source and destination

OrcaSlicer v2.5.0 `OrcaSlicer.cpp:1741–1758` selects `LoadModel | LoadConfig | AddDefaultInstances | LoadAuxiliary` for the first 3MF and calls `Model::read_from_file` once with the requested plate. The relevant owner is `libslic3r/Model.cpp:318, 537–543`, with the BBS/Orca dispatch to `libslic3r/Format/bbs_3mf.cpp:9569–9578` and `_BBS_3MF_Importer::load_model_from_file` at `:1482–1495`: the importer populates the model, embedded config and plate data together. After the file compatibility decisions, the command inspects the same embedded `post_process` vector only when `normative_check` is true (`OrcaSlicer.cpp:1577–1579, 1799–1810`). It reads replacement presets later (`:1953–2024`) and reads explicit retained refresh presets later still (`:2540–2558`), without importing the model again.

The Rust destination remains `ares-core::profiles::entry::CliPresetProject` and `project::load::LoadedProfileProject`, with `project::load::load_project_raw` as the model importer and `project_slice` as the consumer. Explicit preset files and project preset catalogs already move this admission result into the overlay or refresh. Use that same transfer for standalone retained refresh (`ares-cli::{main,native_refresh,project_presets}`), multi-plate preset files (`ares-cli::slice_plates` to `project_slice::cli_plates`), and Native-form selected-plate preset replacement (`ares-cli::direct_project` to `profiles::entry::load_settings`). Delete the temporary load-and-discard CLI admission and the refresh adapter's admitted/unadmitted split. Carry admission through a retained refresh lookup that returns no source rather than reopening the model on the saved-project continuation.

The retained refresh lookup must use the same command context as admission; it must not unconditionally reject the embedded array when `--normative-check=0` is supplied. Admitted paths consume the imported `Project`, sparse embedded settings and preparation state by move. Never put retained defaults into the sparse overlay, deep-copy the geometry, or fall back to reopening admitted bytes. A metadata-only read for source identity, version or substitution reporting is not a model import. The CLI still owns all preset file I/O and reporting.

Included: the preset-taking CLI paths above, preserving plate selection and publication, preset precedence, and the existing byte-based APIs used by other callers. Deferred: changes to version handling, arrangement, action ordering outside preset admission, script execution, and new preset or plater semantics. Saved multi-plate and catalog-only multi-plate paths already do a single model import; do not add a preflight import to them.

## Failure modes to preserve

- Argument, override, and input-file failures already handled before dispatch must still win. The load-settings filename check stays before admission; the catalog route checks the extension before admission and the filename before reading the catalog. Non-3MF bytes must not be admitted as 3MF based on a suffix or rejected earlier by an unrelated import.
- A malformed 3MF must fail at the original import boundary even with missing or malformed presets. Do not check script metadata before the original import finishes: a later invalid package member or model must still win. Preserve the ordinary import's settings validation and its error order; it materializes retained defaults while the overlay import keeps sparse raw settings. Do not feed filled defaults into the overlay or change which errors are reported before or after reading presets.
- With normative checks enabled, embedded `post_process: [""]` and nonempty scripts must reject before catalog, preset/source reads, overlay, machine compatibility, plate selection or print validation. Absent/empty values still proceed. Do not change any existing validation of the final configuration or let a later override hide the embedded array.
- Once admission succeeds, keep the preset read/parse order, including the catalog route's original upward-machine identity lookup. Native-form selected-plate replacement must report a malformed supplied preset as `CLI_CONFIG_FILE_ERROR` (`OrcaSlicer.cpp:1953–2024`), not as an unclassified adapter error. Preserve initial versus later error mapping: no substitution text, upward-machine snapshot, progress, or warnings on an admission failure. Keep the same exit code, stdout, stderr, result.json fields, and no G-code or moves output on failure.
- Move the complete imported mesh and its preparation data, without reimporting or deep-copying it, so import scope, placement and flush-matrix inputs are unchanged. Do not change existing byte-oriented core, WASM or web callers that do not opt into this CLI admission phase.

## Verification

Use identical arguments for Orca and Ares on Native-form selected-plate replacement: `--slice 1 --outputdir out --load-settings malformed.json --load-filaments malformed.json project.3mf`, with an embedded `post_process: [""]` and a present malformed preset. With the default check, the import must reject the project before preset I/O (`-19`); with `--normative-check=0`, the preset parser's error must be reported instead (`-5`). Compare the exit and result report against Orca in both reference modes and require no G-code in either case. This tests the admission boundary, not the number of imports. Native-form `--uptodate` syntax is outside this change.

Run the existing public CLI/core admission, retained refresh, load-settings, catalog, and plate-action cases in both reference modes where applicable. Keep the existing comparisons for successful G-code and reports. Count full model imports before and after at `load_project_raw`, using the same synthetic input and valid presets; require exactly one on each of the admitted success paths, including the retained refresh continuation with no source. Do not add an import counter or a timing assertion to the test suite.
