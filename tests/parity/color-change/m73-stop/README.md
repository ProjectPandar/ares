# M73 stop-time byte oracles

Generated by the **unmodified official OrcaSlicer 2.4.2**, not the
stable-options diagnostic. Source boundary: `GCodeProcessor.cpp:5715`
(stop registration), `:576-579` (elapsed update), `:1098-1101` (initial C),
`:1260-1293` (next-stop / last-minute formatting).

Reproduce from the committed Ender-3 3MF and ordinary user-template overrides:

```sh
ORCA_APPDIR=/path/to/official-2.4.2/squashfs-root \
  node web/e2e/colorChangeOracle.mjs "$PWD/target/color-change-byte-oracle"
cargo nextest run -p ares-core --test processed_color_stop
```

The generator writes each input 3MF, overrides, raw official `plate_1.gcode`
and log. `official.gcode` here normalizes only its single generator identity /
timestamp line to `; generated by <SLICER> 2.4.2`. No other bytes (including
M73 P/R and C) are ignored. `oracle.json` pins normalized SHA-256 and C lines.
The Rust tests save complete actual/expected files under
`target/color-change-stop-oracle/` for reproducible diffing.

- `normal`: SYNC before ColorChange/Pause can leave already-flushed stop IDs
  at zero; later positive stop emits C1 then C0.
- `stop-times`: no SYNC; exercises C1 and nonfinal last-minute C0.01.
- `zero-before`: color change before model use; initial C0 still required.

All fixtures exercise full public byte-in/options-to-G-code output, not a
mock formatter. Their RED must precede the processor-only GREEN commit.
